# BGNext

为金团记账、拍卖和结算准备的社区插件。团长管理起拍价与账单，团员整理心愿和个人心理价，自己的角色进度集中查看。BGNext 基于官方 **BGLite 纯净版 2.4.2** 独立维护，重视日常操作效率、性能和本地隐私。

> [!IMPORTANT]
> **安全、隐私和合规优先于功能完整度、开发速度、下载量、排名及任何经济激励。**
> 任何功能只要存在无法合理排除的隐私、安全、平台规则或知识产权风险，就不会合并或发布。

## 项目缘起

BGNext 发起于对网易 DD 公开举办的「BGLite 增强版开发激励活动」的响应。我们以活动提供的 BGLite 上游为起点，通过公开审查和社区协作，逐步提供稳定、实用、易用的团队协作功能。

本项目是独立、非官方的社区项目，不代表网易、暴雪或 BGLite 原作者的官方立场。活动名称只用于说明项目缘起，不构成合作、认证、推荐或商业背书。

## 主要功能

- 团队账单：保留原版 BGLite 的高密度金团表格，支持拍卖、记账、交易与邮件核对；交易记录同时区分“已交易”和“待核对”，尽量呈现实际交付数量与双方金币。
- 价格预设与待拍队列：团长按团本保存多套起拍价方案，可把装备排入当前团待拍队列并逐件确认开拍；表格装备 Alt+右键按预设开拍，Ctrl+右键修改单件价。团员可保存个人心理价，旧价格字符串可预览导入。
- 团队拍卖就绪检查：进团后查看成员拍卖端就绪状态，未响应不会被误标为未安装。
- 可切换的 BGNext 预览外观：保持原版账单布局和半透明背景，经典外观仍为默认。
- 心愿清单：按副本、难度和首领整理目标装备。新选装备默认“备选”，滚轮按“备选 < 次 BIS < BIS”切换，文字徽标显示优先级。已有优先级不重置，旧字符串仍能导入。
- 结算前检查：集中提示欠款、账单缺项及待核对的交易；证据不足时保留待确认，辅助核对但不代替团长判断。
- 可选团长工具：支出模板只填空行；拍卖中心集中查看当前拍品并复核明显异常出价；实收与分金预览严格区分账面金额和已证实交易。
- 可选本地成交摘要：默认关闭，仅在手动确认后保存物品、金额、副本、时间和“是否本人”，可设置 30/90/180 天并一键清空。
- 角色总览与装备过滤：只记录自己登录过的角色；正式服团本进度按 Boss 与难度分别统计，按变化范围刷新以减少不必要的重复工作。
- 存储与隐私：可手动确认清理停用的旧历史数据；登录和升级不会自动删除。清理前请先备份 WTF。

输入 `/bgn` 或 `/bgnext` 打开插件。个人工具数据仅保存在本地；当前团交易与邮件核对只保留最近一团，最长七天，不建立其他玩家历史档案。

## 项目目的

1. 在明确合规边界内维护 BGLite 的稳定性和游戏版本兼容性。
2. 通过 Issue、Pull Request、代码审查和测试记录进行透明共创。
3. 让玩家清楚知道插件读取、保存、导出或传输了什么数据。
4. 为代码、测试、翻译、设计、文档和合规贡献建立公平的认可机制。
5. 将全部项目收入用于慈善，并公开可核验的收支与捐赠记录。

## 不可逾越的边界

本项目不会接受：

- 未经玩家许可收集、保存或传播账号、角色、设备、聊天、战斗、交易等信息；
- 在插件加载、角色登录、进入副本或其他游戏行为发生时自动上传或同步数据；
- 隐藏采集、隐藏通信、遥测、跟踪标识、后门或远程控制；
- 博彩、现金交易导流、刷量、诱导重复下载、强制分享、强制关注或强制好评；
- 未经授权的代码、UI、图片、字体、声音或文案；
- 规避平台审核、误导审查人员或在后台代替玩家完成敏感行为的实现。

详细规则见[合规边界](docs/policies/COMPLIANCE.md)、[隐私政策](docs/policies/PRIVACY.md)和[安全政策](SECURITY.md)。有疑义的功能先暂停，完成评估或取得平台书面确认后再决定。

## 安装

普通玩家应优先使用 GitHub Release 或通过网易 DD 等适用平台审核的正式版本，不要直接下载仓库源码替代发布包。

安装或更新：

1. 下载发布页提供的 ZIP，并确认来源和版本号。
2. 完全退出游戏并备份 WTF；解压后应得到包含 `BGNext.toc` 的 `BGNext` 文件夹。
3. 将该文件夹复制到对应游戏客户端的 `Interface/AddOns/` 目录。
4. 完全退出并重新启动游戏，在插件列表中确认 BGNext 已启用。

更新时先移走旧 BGNext 插件目录，再放入新版，避免旧文件残留；不要删除 WTF 中的设置。BGNext 不需要 BGLite_KZ 等扩展，不要同时启用 BGLite、BiaoGe 或依赖它们的扩展。

维护者使用 `tools/build-release.ps1` 从实际加载清单生成发布包。该流程会排除仓库中的测试、开发文档及已隔离的旧历史/整表接收源码；禁止直接压缩整个仓库作为 Release。
