# 功能与合规边界

## 决策原则

BGNext 将安全、隐私和合规置于功能数量、开发速度、下载量、活动排名及经济利益之上。功能是否受欢迎不能代替合规判断。

评审依据包括适用法律法规、《魔兽世界》国服运营规则、网易 DD 平台审核要求、「BGLite 增强版开发激励活动」最新公开规则、知识产权与权利人授权，以及项目自身的安全隐私政策。平台规则更新后，应重新评估受影响功能。

## 通常允许

在不引入额外敏感数据或游戏外通信的前提下，以下方向通常可以进入常规评审：

- 本地界面、可访问性和操作体验优化；
- 本地配置、记录、查询、统计和报表展示；
- 玩家主动发起的团本信息整理与团队协作；
- 使用游戏公开 API 获取当前角色可见的信息；
- 用户主动触发、内容完全可见的文本复制或本地导出；
- 不改变数据范围的兼容性、性能、稳定性和错误修复；
- 原创且权利清晰的翻译、图标、声音和文档。
- 按 ADR-0003 对合法取得的插件版本进行可追溯研究，用于理解玩家可见交互、版本差异和兼容需求，并由 BGNext 独立编写最终实现。

“通常允许”不等于自动通过。Pull Request 仍需说明数据、通信、自动化、素材和测试情况。

## 必须单独评估

以下改动必须先建立 Issue，完成书面合规评估，必要时取得平台确认：

- 新增或改变游戏内插件消息、团队频道、密语协议及接收对象；
- 自动发送聊天、出价、交易、邮件或其他可能代表玩家意图的行为；
- 处理其他玩家的角色名、出价、交易、战斗或聊天信息；
- 跨角色、跨账号、跨服务器或跨版本合并本地记录；
- 导出、复制、编码、压缩或批量整理玩家数据；
- 读取 SavedVariables 之外的新数据源；
- 引入第三方库、字体、UI、图片、声音或大段文案；
- 与 BGLite、历史 BiaoGe 或其他插件进行协议兼容；
- 任何审查者无法明确判断是否属于平台允许范围的功能。

评估记录必须说明必要性、最小数据范围、用户触发方式、接收方、失败处理、退出方式和替代方案。

## 禁止

项目不接受：

- 未经玩家许可越权采集、保存、关联或传播隐私信息；
- 在加载插件、角色登录、进入副本或其他游戏行为发生时自动向游戏外上传或同步；
- 隐藏采集、隐藏传输、遥测、远程日志、设备指纹或跟踪标识；
- 后门、远程控制、外部可执行程序、动态下载并执行代码；
- 绕过玩家明确操作，在后台代表玩家执行敏感决定或隐藏自动化；
- 规避平台审核、伪装真实功能、混淆数据流向或删除审计证据；
- 博彩、现金交易、代练、黑灰产或其他违规导流；
- 刷量、买量、诱导重复下载、强制分享、强制关注或强制好评；
- 虚假宣传安全性、官方身份、功能效果或活动关系；
- 未经授权复制、改写、换皮或重新打包他人的代码、UI、图片、字体、声音和文案；
- 以活动排名、赞助或维护者个人利益为由绕过审查。

## Pull Request 合规清单

每个运行时 Pull Request 必须回答：

1. 改动解决什么玩家问题？
2. 读取哪些数据？为什么每一项都必要？
3. 保存哪些数据？保存在哪里？
4. 是否发送游戏内消息？频道、接收方、内容和触发条件是什么？
5. 是否产生游戏外导出或传输？是否由用户主动触发并完整告知？
6. 是否代表玩家自动执行聊天、出价、交易或其他行为？
7. 是否包含第三方代码或素材？权利依据是什么？
   如果研究过第三方插件，还必须披露插件与版本、获得的行为结论、由此产生的需求，以及 BGNext 如何保持独立实现。
8. 如何测试隐私、安全、兼容性、失败路径和退出方式？
9. 是否修改 BGLite 2.4.0 基线文件？逐文件原因是什么？
10. 是否需要网易 DD 或其他适用平台重新审核？

任何答案缺失、含糊或与代码不一致时，Pull Request 不进入合并阶段。

## 疑义与紧急处理

有疑义的功能默认暂停。维护者可要求补充最小复现、数据清单、通信协议、素材授权或平台书面意见。

已发布功能出现重大安全、隐私或合规风险时，维护者可以立即撤回 Release、关闭功能入口、回滚提交并建议用户停用相关版本。后续恢复必须完成重新审查和必要的平台审核。
