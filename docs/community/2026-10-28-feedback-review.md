# 角色总览及常用入口反馈自查

检查日期：2026-10-28。以当前修复分支为对象，包含此前角色逐项删除和未缓存装备条目保护；不把源码检查、模拟界面或自动测试表述为游戏实测。本轮未安装或发布。

## 1. 角色金币总计不完整

未复现汇总计算错误。OwnCharactersAdapters.readMoney 读取当前登录角色的 GetMoney；模型保存本人角色最近一次快照。OwnCharactersView.project 只对显示范围内的行求和，先过滤服务器及角色等级，再合计原始铜币值，最终显示整数金币。

因此未在启用功能期间登录采集的角色、其他服务器角色、默认隐藏的非满级角色、其他客户端版本族及其他账号并不自动加入当前显示合计。离线角色是最后一次记录值，不能实时查询。既有测试覆盖金币相加、跨服筛选、非满级过滤与显示开关、PLAYER_MONEY 事件以及部分更新保留其他字段。

可直接回复：

> 金币合计统计的是当前显示范围内、已登录记录的角色持有金币。请让需要统计的角色分别登录一次；其他服务器角色可按住 Shift 查看，非满级角色需在“设置 → 角色总览”勾选“显示非满级角色”。离线角色显示最近记录值。如果这样仍有遗漏，请补充插件版本、客户端版本，以及是哪几个角色的金额没有计入，我们再针对核对。

## 2. 看不到团本 CD 进度

尚未复现反馈所说的统一故障，不能判定所有用户环境均正常。检查确认登录及手动刷新会请求 RequestRaidInfo；UPDATE_INSTANCE_INFO 只读取更新，不循环请求。GetSavedInstanceInfo 以第14项实例 ID 对应本地列；奥杜尔另有25人限制。已保存状态到重置时间后过期，不保留为历史进度。列可以被用户隐藏，部分旧团本默认隐藏；接口不可用时不伪造进度。

现有读数及视图测试覆盖毒蛇、风暴、黑曜石、永恒、奥杜尔、局部击杀、过期、不同版本族和正式服难度隔离，但这些不证明反馈用户的真实客户端 API 返回值正常。

可直接回复：

> 角色总览需要分别登录角色才能更新进度。先用 `/bgn role` 打开总览，检查所需团本列是否开启，再点窗口的刷新按钮。若游戏自带“团队信息”已有进度，但总览刷新后仍不显示，请提供插件版本、游戏客户端版本、具体团本及两处显示情况；这条反馈目前还在排查，暂不能确认原因。

## 3. 找不到心愿清单

入口存在：WishlistUI 创建主窗口底部“心愿清单”标签，随“功能管理”的 wishlist 开关显示或隐藏；按当前选择的副本切换心愿格。相关开关、选择器、存取与导入导出有既有自动测试。

可直接回复：

> 输入 `/bgn` 打开主窗口，点击底部“心愿清单”，再选择上方副本即可。如果看不到这个标签，请到“设置 → 功能管理”开启“心愿清单”。

## 4. 怎样查看哪些人出了价

入口存在：自动拍卖卡片的出价记录提示；主窗口左上“拍卖记录”里，对有 log 的成功拍卖条目右键菜单提供“出价记录”，鼠标悬停查看内容。拍卖成功聊天附加记录链接还受“拍卖成功的聊天消息后面增加[出价记录]”设置控制。不能据此承诺恢复插件未接收到的手动拍卖出价，或已经清空的记录。

可直接回复：

> 自动拍卖时可把鼠标移到拍卖卡片的出价记录处查看。拍卖成功后，也可以点主窗口左上“拍卖记录”，右键对应条目，悬停“出价记录”查看出价人和金额。需要插件当时实际接收到出价，手动聊天拍卖或已经清空的记录不能补查。

## 5. 角色总览橙武不显示装等

已复现显示缺口并修复。原 tracked-items 投影只有物品 ID 和数量，绘制器只为已有 itemLevel 或数量大于1的物品创建数字，因此单件“已有”橙武无装等，多件时还可能显示数量。当前仅在 legendaryItems 列绘制时读取 Blizzard 物品元数据，不增加保存字段；升级物品列继续显示数量，已装备武器继续显示采集装等。

缓存未就绪时显示 `?`，通过 Blizzard Item:CreateFromItemID 的加载完成回调补全。回调检查窗口身份、绘制版本与可见性，防止旧回调修改复用文字。缺失 API、错误或非法装等保留未知，不伪造数值。

新增回归测试驱动真实 View、UI.layout 和 UI.Draw：先观察旧实现缺少数字，再验证已缓存显示、异步补全、旧回调隔离、关闭窗口、命名空间 API、API 抛错和无效读数；装备装等及材料数量均保持原行为。

可直接回复（当前尚未发布）：

> 这条已确认是显示缺口，已经修复，会随下一次更新提供。角色总览“已有”橙武图标会直接显示装等，信息未加载时先显示 `?`，加载后自动补全。

## 6. 无法对账或找不到对账按钮

当前主窗口底部已有“对账”页，DuiZhang.lua 创建“开始对账”按钮。需要先点击，随后接收当前团队接下来通报的一份完整账单；不会后台回读旧聊天。捕获绑定当前团队的一个账单来源，超时、越界、停止、离团或重载会清理临时结果。既有 LedgerCapture 测试覆盖来源绑定、错误来源拒绝、离团与容量/超时保护；未根据笼统反馈改动协议。

可直接回复：

> 主窗口底部有“对账”页：先点“开始对账”，再请团长重新通报一份完整账单。先前已经发过的账单不会自动补读；重载或离团后要重新开始。如果页面里没有按钮，或重新通报后仍无结果，请提供插件版本和账单来源插件名称。

## 7. 增加节日 CD 进度

当前角色总览目录没有节日活动 CD 列，属于未实现的需求，不是已支持列突然失效。不同活动可能使用每日奖励资格、任务或副本锁定等不同机制，不能直接把普通团本 CD 当作活动奖励资格。本轮未新增数据采集、活动 ID 或未经验证的进度。

可直接回复：

> 目前角色总览暂未提供节日活动 CD／奖励进度，这条已记录为功能建议。可以补充具体活动名称及希望显示“副本击杀进度”还是“今日奖励是否领取”，后续按活动机制评估。

## 改动边界

本轮代码仅调整原创角色总览绘制器，未改保存结构、金币求和、团本采集、清空规则、心愿、拍卖发送或对账协议，也没有复制第三方实现。物品元数据仅用于本地显示；异步状态仅在内存，不产生聊天或插件消息。真实客户端、网络、其他插件组合和反馈用户具体环境仍未验证，不能声称全部反馈均已排除。
