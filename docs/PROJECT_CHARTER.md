# BiaoGe Next 项目治理章程

## 使命

BiaoGe Next 在 BGLite 纯净版基础上，通过公开协作维护安全、稳定、实用的《魔兽世界》团队协作插件。项目以玩家权益为中心，安全、隐私和合规高于功能数量、发布速度、活动排名和经济收益。

## 项目身份

项目响应网易 DD 公开举办的「BGLite 增强版开发激励活动」发起，但属于独立、非官方社区项目，不代表网易、暴雪或 BGLite 原作者的官方立场。

## 角色

### 维护者

维护者负责：

- 维护路线、Issue 和 Pull Request；
- 保护基线、分支、Release 和安全报告；
- 组织技术、兼容性、安全、隐私、合规和权利审查；
- 保证发布材料真实、完整并通过适用平台审核；
- 维护贡献者名单及慈善收支公开记录；
- 在出现重大风险时及时停止传播、回滚或下架。

维护权限不是荣誉称号。长期不参与、滥用权限、隐瞒利益冲突或绕过项目规则时，可以暂停或移除权限。

### 贡献者

贡献者通过 Issue、Pull Request、测试、翻译、设计、文档、安全报告或合规建议参与。贡献者只对其提交和声明的准确性负责，不因被列入感谢名单而承担整个项目责任。

### 审查者

维护者可以邀请具有相关经验的人进行专项审查。涉及隐私、安全、自动化、外部导出、协议通信或重大版权风险的改动，应取得至少一名未直接实现该功能的审查者意见；无法完成独立审查时暂缓发布。

## 决策方式

项目优先通过公开 Issue 和 Pull Request 形成基于证据的共识。决定应记录问题、方案、风险、测试和结论。

出现分歧时，依次考虑：

1. 玩家安全和合法权益；
2. 法律、游戏规则、平台规则和权利状态；
3. 数据最小化与可撤销性；
4. 兼容性、稳定性和维护成本；
5. 用户体验和功能价值。

下载量、活动排名、赞助金额和个人关系不得覆盖前四项。

## 合并规则

- `main` 只接受经过审查并通过验证的变更；
- 功能和重要行为变化必须关联 Issue；
- Pull Request 必须完整披露数据、通信、自动化、素材和测试情况；
- 基线文件改动必须逐文件说明，不得通过刷新哈希掩盖改动；
- 有重大风险或权利不清的改动暂停合并；
- 合并不代表可立即发布，正式版本仍需完成发布检查和平台审核。

## 发布责任

每个 Release 应包含版本号、支持的游戏版本、变更说明、校验值、已知问题和贡献者致谢。发布包只包含插件运行所需文件，不混入仓库治理资料。

未审核通过的新版本不得替换稳定版本。发现重大风险时，维护者可以先撤回 Release、关闭下载或建议停用，再补充公开说明。

## 利益冲突与财务

维护者和审查者必须披露可能影响判断的雇佣、商业、亲属、赞助或受赠机构关系，并在必要时回避。

全部项目收入用于慈善，赞助不能换取功能优先级、合并、权限、署名排序或审核豁免。财务规则见 [CHARITY.md](CHARITY.md)。

## 章程变更

修改本章程必须通过独立 Pull Request，清楚说明原因和影响，并给予社区合理审阅机会。不得通过章程修改降低既有的安全、隐私和合规红线。
