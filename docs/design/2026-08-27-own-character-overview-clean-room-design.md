# BGNext 自有角色总览洁净室高保真设计

日期：2026-08-27  
状态：已由维护者确认，等待实施计划与实现

## 1. 目标

在 BGLite 2.4.0 上游分发快照之上，独立实现 BGNext 的“自有角色总览”。可见信息结构、操作习惯和主要布局应与玩家熟悉的 BiaoGe 角色总览保持高保真等效，同时所有运行代码必须从零编写，只依赖 BGLite 已有能力、暴雪公开 API 和暴雪自带资源。

“高保真等效”包括页面分区、角色与字段的行列关系、字段顺序、颜色语义、窗口行为、设置入口和快捷操作；不包括复制、改写或转换 BiaoGe/社区插件源码、图片、字体或其他素材。

## 3. 用户可见结构

角色总览是一个动态尺寸的横向表格窗口，角色始终是行，团本、货币、装备和其他分类始终是列。禁止退回“每个角色一张卡片”或“装备图标纵向堆叠”的自创布局。

### 3.1 上半区：角色团本完成总览

- 绿色标题：`< 角色团本完成总览 >`。
- 标题后显示灰色的下一次团本重置倒计时。
- 第一列表头显示当前可见角色数和“装等”语义。
- 每个角色占一行；角色名使用职业颜色，装等紧随角色名显示。
- 后续列由当前客户端的团本、周常、声望或专业冷却目录生成。
- 已完成状态使用绿色勾；进度型字段显示实际进度；未知或不可用状态留空，不伪造完成结果。
- 黑色与灰色背景交替显示角色行。

### 3.2 下半区：角色货币/装备总览

- 绿色标题：`< 角色货币总览 >`。
- 标题后显示灰色操作提示。
- 第一列表头显示当前可见角色数和“等级”语义。
- 每个角色占一行；后续列显示当前客户端可用的专业、装备分类、货币、物品数量、荣誉、金币等信息。
- 装备类字段使用物品图标，并在图标上显示装等或数量；悬停展示官方物品提示。
- 数值列保持原始数值语义和对应颜色。
- 最后一行提供适用字段的合计；不能求和的装备或状态列不显示虚假合计。

### 3.3 动态布局

- 窗口宽度由当前启用列、标题实际宽度和装备图标数量共同决定。
- 窗口高度由两个分区、表头、角色行和合计行共同决定。
- 不使用固定宽度截断字段，不让内容溢出背景板。
- 不引入横向滚动条；用户通过列显示设置控制信息密度。
- 线条、黑灰交替行、职业色、绿色标题、灰色提示和图标尺寸须通过游戏内截图逐项校准。

## 4. 列显示设置

角色总览右上角保留齿轮入口。点击后打开 BGNext 设置中的“角色总览”，而不是建立一套与原版习惯不同的临时菜单。

设置页分为：

1. 团本完成列；
2. 货币、装备及其他资源列。

每个当前版本可用的列都有独立复选框。取消选择后：

- 该列立即从总览中隐藏；
- 窗口宽度立即重新计算；
- 原始角色快照不被删除；
- 重新勾选后恢复显示。

列设置以客户端版本族为作用域保存。例如周年时光服隐藏“熔火之心”不会改变正式服或熊猫人客户端设置。设置页提供“恢复当前版本默认列”，只重置显示偏好，不清理角色数据。

## 5. 入口与交互

- 在 BGLite 主界面右下角提供“角色总览”入口，位置与玩家既有操作习惯一致。
- 鼠标悬停入口时显示临时总览，移开后自动关闭。
- 鼠标中键或 `Ctrl+左键` 将窗口固定。
- 固定窗口可拖动，并把位置保存在 BGNext 本地设置中。
- 默认仅显示当前服务器角色；按住 `Shift` 临时显示全部本地服务器角色。
- 同名跨服角色显示短服务器前缀，不能合并为一条记录。
- 右上角依次提供设置、刷新、关闭操作。
- 支持 `/bgn role` 和 `/bgnext role` 打开固定窗口。
- 删除角色必须通过角色行右键菜单并二次确认；删除键使用服务器 ID 与角色名的完整组合。
- 刷新只重新读取当前角色并重建视图，不扫描其他玩家，不发送消息。

## 6. 数据模型与生命周期

所有新增数据保存在 `BiaoGe.BGNext.ownCharacters`，并加入数据清单。只允许记录用户实际登录过的当前角色。

建议逻辑键：

`ownCharacters[clientFamily][realmId][playerName]`

每条记录是最近一次观察快照，可包含：

- 角色名、服务器 ID、规范化服务器名和阵营；
- 职业、等级、最近装等和更新时间；
- 当前装备槽的物品 ID、物品链接必要字段及装等；
- 当前版本允许展示的货币和背包物品计数；
- 自己的团本锁定/完成状态及其官方重置时间；
- 自己的专业及专业冷却状态；
- 自己的金币及其他明确列入版本适配器的字段。

更新采用覆盖快照，不建立每周历史、装备历史、货币变化历史或跨角色行为画像。

- 装备、等级、货币和金币保留最后一次本地登录快照，直到角色被再次更新或用户删除。
- 团本完成状态带官方重置边界；过期后视为无当前周记录，不能保留为历史周数据。
- 当前团交易/邮件的七天限制不套用到自有角色最近快照。
- 用户可以删除单个角色、清空角色总览数据或禁用模块。

## 7. 隐私与通信红线

- 不采集、保存或显示其他玩家的数据。
- 不通过目标头像、团队名单、战斗记录、聊天或交易记录建立角色档案。
- 不接入 BiaoGeAccounts 或任何跨账号同步插件。
- 不调用 `SendAddonMessage`、`C_ChatInfo.SendAddonMessage` 或 `SendChatMessage`。
- 不上传、不遥测、不联网，不建立账号关联标识。
- 不把自有角色快照用于评分、排行、PUG 审核或团队管理。
- 不读取或迁移旧 BiaoGe 角色总览及跨团历史数据。

## 8. 全版本架构

渲染器和数据模型共用，客户端差异由只读版本适配器隔离。适配器必须声明：

- 客户端版本族；
- 可用团本与周常列；
- 可用货币、装备、专业和资源列；
- 每个字段的官方 API 获取方式；
- 默认显示状态、标题、颜色语义、列宽类别及排序顺序；
- API 不可用、值受保护或物品未缓存时的降级结果。

需要覆盖 BGLite 当前声明的版本族：

- 经典永久 60 与探索服；
- TBC；
- 巫妖王及周年时光服；
- 大地的裂变；
- 熊猫人；
- 正式服。

当前客户端不存在或 API 无法可靠读取的字段必须隐藏。禁止为了“全版本一致”而显示假值。第一轮以周年时光服完成完整视觉和实机验收；其他版本必须先通过加载、API 存在性和投影测试，再逐版本补实机截图。

## 9. 组件边界

建议实现拆分如下，名称可在计划阶段微调，但职责不得重新混杂：

- `OwnCharacters.lua`：本地快照模型、校验、更新、删除和清空。
- `OwnCharactersAdapters.lua`：版本识别、适配器注册与安全 API 包装。
- `OwnCharactersCatalog*.lua`：各版本的列目录与字段读取描述。
- `OwnCharactersView.lua`：把快照和设置投影成不含 WoW Frame 的纯表格模型。
- `OwnCharactersUI.lua`：按投影结果创建表格、图标、提示、背景和动态尺寸。
- `RoleOverviewEntry.lua`：主界面入口、斜杠命令、悬停和固定窗口生命周期。
- `RoleOverviewSettings.lua`：列选择、按版本保存和恢复默认。

数据采集不能直接操作 UI；UI 不能直接遍历 SavedVariables；版本差异不能散落在渲染器中。

## 10. 错误处理

- API 不存在：适配器返回“不支持”，对应列不进入投影。
- API 暂时无结果或物品未缓存：当前单元格留空或显示安全占位，异步数据到达后刷新，不抛错。
- SavedVariables 类型损坏：只重建 BGNext 自有角色子树的最小安全结构，不读取旧历史补齐。
- 角色快照字段异常：忽略该字段，保留其他合法字段。
- 窗口超出屏幕：恢复安全默认位置；不得修改其他插件窗口。
- 版本目录遗漏：模块保持可加载，并在本地调试信息中标记缺失，不能影响 BGLite 拍卖主体。

## 11. 测试与验收

### 11.1 自动化测试

- 模型只接受当前登录角色及白名单字段。
- 同名跨服角色保持独立。
- 更新覆盖旧快照，不生成历史数组。
- 团本状态在重置时间后失效。
- 版本适配器只输出当前版本可用列。
- 隐藏列后投影与动态宽度同步变化，数据仍保留。
- 角色排序、短服务器前缀、合计行和空值行为稳定。
- 删除必须使用完整角色键，不能误删同名跨服角色。
- UI 模块不包含通信调用。
- Lua 5.1 测试、基线完整性和覆盖清单全部通过。

### 11.2 游戏内验收

在相同分辨率和 UI 缩放下，将 BGNext 与维护者提供的 BiaoGe 参考截图逐项对照：

- 两个分区和标题；
- 角色为行、分类为列；
- 列顺序、列宽与窗口动态尺寸；
- 字体、颜色、分隔线和黑灰交替行；
- 装备图标尺寸、数量/装等位置和悬停提示；
- 完成勾、进度、合计与空值；
- 悬停、移开、固定、拖动、刷新、设置、关闭和 Shift；
- 隐藏“熔火之心”“泰坦碎片”等列后的即时重排；
- 两个同名跨服角色保持两行。

没有实机截图对照的项目必须标记“未验证”，不能用自动化测试替代视觉验收。

### 11.3 原创性复核

完成后对新增代码执行：

- 与 BiaoGe v2.3.5 的文件哈希比对；
- 排除 BGLite 官方基线后的连续非平凡代码片段比对；
- 素材哈希比对；
- 提交历史和测试先后顺序复核。

发现 BGLite 官方基线以外的实质性复制证据时，停止合并并重新独立实现。不得通过机械改名或重排消除相似度命中。

## 12. 发布门槛

本功能只有同时满足以下条件才可进入 PR 合并评审：

1. 洁净室边界和数据清单已更新；
2. 自动化测试、基线校验和隐私扫描全部通过；
3. 周年时光服游戏内主要状态验收通过；
4. 代码与素材来源审计未发现不允许的复用；
5. 不含旧角色总览迁移、其他玩家数据、跨账号同步或历史画像；
6. PR 保持可审核的提交粒度，角色总览独立完成后再开始下一项功能。

在满足以上门槛前，不合并 PR，不发布 Release。
