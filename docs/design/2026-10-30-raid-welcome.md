# 入团欢迎语：设计、实施与通信评估

状态：维护者已确认设计并授权实施；本机模拟验证不代表实机或平台批准。

目的：团长主动开启后，在新人加入当前团队时发布自己预先填写的单条欢迎语，例如语音频道和集合说明。独立编写，不读取或复制第三方插件实现；不改集合石插件。

范围：设置“其他功能”页下方新增“入团欢迎语”区块，默认关闭，空文本不发送。仅普通团队的当前团长发送 RAID 普通聊天；不发小队、随机副本队伍、密语、团队警告、插件消息或游戏外消息。不增加命令执行、占位符或动态玩家信息。跟踪 Issue：#141。

数据：本地 `settings.raidWelcome` 只保存 `enabled` 布尔值和 `text` 文本；用户可编辑清空。文本限制为一行、至多240个UTF-8字节，拒绝控制字符和WoW管道标记，不拆分多条。提示用户内容会公开到团队，勿填个人敏感信息。当前成员GUID只在内存比较当前名单和待发批次，不创建稳定记录；不存成员、入退团历史或发送日志。关闭操作即使遇到无效草稿也立即成功，保留上次有效文本。

触发及停止：建立当前名单基线，不向已有成员补发。仅后续名单增加才安排发送；3秒合并，发送间隔至少30秒；发送前复核团长、开关、内容和新人仍在团。重复名单事件、排序和小队调整不触发。开启、修改文本、获得团长、登录/重载/切换世界均重建基线；关闭、失去团长、离团、切换世界取消待发，不重试失败消息。战斗中不发；遇到战斗丢弃待发而非稍后补发。无轮询。

替代方案：手动复制发言，或者只提示团长点击发送；自动模式的必要性是减少重复操作，代价是新人入团时当前所有团员都能看到同一公开文本。明确开关、固定接收方、内容提示、频率限制和即时停止控制该风险。此评估只允许本地开发及审核，不宣称平台许可；发布前披露新增自动聊天并复核当时平台规则和客户端发送限制。

实施计划（writing-plans）：
1. 先用真实控制器的模拟事件测试观察RED，独立实现名单差分和一次性计时器。
2. 补足禁用、世界离开、权限丢失、撤回新人、限流及失败不重试测试，逐项RED/GREEN。
3. 在现有设置入口增加独立区块与三语文本，接入TOC，逐项审核加载图与哈希。
4. 更新数据清单、兼容性和未发布日志；跑完整高风险验证，独立审查通信路径，记录实机证据缺口。

验收：只发送明确配置的文本到RAID；每批新人至多一条；已有成员不补发；停止条件取消旧回调；其他功能测试保持通过。
