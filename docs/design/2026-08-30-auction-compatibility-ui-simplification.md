# 拍卖兼容界面简化设计

## 目标

拍卖发起窗口不再要求玩家理解通信协议或选择已经不存在的拍卖模式。当前团队可能混用旧版兼容插件，因此 BGNext 默认采用兼容范围更广的第一代拍卖协议。

## 玩家可见行为

- 删除“拍卖版本”及其第一代、第二代下拉框。
- 删除“拍卖模式”及只有“常规模式”的下拉框。
- 删除只服务于第二代协议的“重置阈值”输入框和相关提示。
- 保留拍卖时长、起拍价、拍卖数量、快捷金额和开始拍卖按钮。
- 玩家开始拍卖时无需额外选择，行为等同于原来的“第一代拍卖 + 常规模式”。

## 兼容边界

- 发起拍卖固定使用第一代 `BiaoGeAuction` 兼容协议。
- 拍卖模式固定为 `normal`。
- 第二代接收和处理代码暂时保留，避免破坏其他兼容客户端发来的现有拍卖；BGNext 自己不再通过界面发起第二代拍卖。
- 不同时发送两代开始消息，避免新版客户端显示重复拍卖框。
- 保留已有 SavedVariables 字段，不迁移、不清除玩家旧设置；这些字段不再影响发起行为。

## 实现范围

- 只调整现有拍卖发起窗口和发送参数，不重写拍卖框、出价、自动出价或协议接收器。
- 永久 60、周年 TBC、周年时光服、熊猫人和正式服共享相同行为。
- 探索赛季不增加任何新入口或专属处理。

## 验证

- 测试发起窗口源码不再创建版本、模式和重置阈值控件。
- 测试所有开始拍卖路径固定调用第一代协议并传入 `normal`。
- 保留第一代小数拍卖编号回归测试。
- 运行完整 Lua 测试、基线完整性检查、发布包检查和 `git diff --check`。
- 实机分别验证单件与多件拍卖；混用旧插件时确认只出现一个拍卖框。
