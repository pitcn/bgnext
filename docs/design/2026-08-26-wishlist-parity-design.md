# BGNext 心愿清单原版等效设计

日期：2026-08-26  
状态：已由维护者确认

## 1. 目标与优先级

BGNext 心愿清单必须恢复原版 BiaoGe v2.3.5 对应功能的可见布局、字段含义、控件位置、操作顺序、键鼠交互、提示、状态反馈和提醒流程。现有 BGNext“输入物品 ID 后显示平铺列表”的简化页面不符合验收要求，必须被替换，不能作为并行的第二套正式界面保留。

当“原版完全等效”与项目隐私、安全或合规红线冲突时，红线优先。被排除的功能不得通过改名、隐藏入口或兼容模式恢复；除此之外，不得以“优化”为由自行改变原版用户习惯。

## 2. 来源与实现边界

- BGLite 2.4.0 是可维护的运行基线。
- 历史 BiaoGe v2.3.5 只用于观察和记录用户可感知行为、界面关系和文本数据格式。
- 新心愿模块使用独立编写的 Lua，不复制、改写或重排历史 BiaoGe 的 Lua 代码结构。
- 不复制历史 BiaoGe 的图片、字体、声音或其他素材；只复用权利清晰的 BGLite/游戏内置资源，或使用 BGNext 原创资源。
- 对照记录可以描述尺寸、位置、交互和状态，但不得把历史源码片段提交到 BGNext 仓库。

## 3. 功能范围

### 3.1 必须恢复

1. 心愿清单位于原版对应的主界面页签位置。
2. 按当前副本、难度、Boss 和固定心愿格组织装备，不使用平铺物品列表作为正式工作区。
3. 难度标题、Boss 行、心愿列、物品编辑格、装备图标、物品链接和已掉落提示的层级与原版一致。
4. 支持从光标放入装备、在可用装备列表中选择，以及原版已有的装备录入方式。
5. 支持右键删除心愿装备。
6. 支持原版的 Tab、方向键、Enter、Shift 点击、Ctrl 点击及鼠标悬浮行为；每个组合键以实测行为清单为准，不凭记忆补充。
7. 心愿格发生变化后立即更新本地存档、图标、物品提示和相关本地标记。
8. 只允许把当前副本正常 Boss 掉落、且能够确定难度和 Boss 归属的装备设置为心愿；无法判断时拒绝并给出原版等效错误反馈。
9. Boss 心愿格已满时拒绝新增并给出原版等效反馈。
10. 清空当前副本心愿必须使用原版入口和确认流程。
11. 心愿装备掉落时显示本地提醒；进入 BGLite 当前拍卖流程时显示本地提醒并使用权利清晰的提醒声音。
12. 保留原版位置和操作方式的“导入心愿”“导出心愿”。

### 3.2 明确排除

- 通报心愿及团队、队伍、公会、密语频道选择。
- 查询团队心愿竞争、团队心愿汇总和任何其他玩家心愿收集。
- 自动发送、广播或同步本人心愿。
- 心愿分享链接、云同步、遥测和游戏外自动上传。
- 跨角色查看其他玩家，或把不同玩家心愿关联成画像。

上述控件不创建，也不保留可被重新启用的隐藏处理器。删除右侧传播区后，不自行设计新的功能填充该区域；其余主工作区保持原版对齐关系。

## 4. 数据模型

心愿数据只写入 `BiaoGe.BGNext.wishlist`，按服务器、本人角色、副本、难度、Boss 和心愿格保存：

```lua
wishlist[realmId][player][raidId][difficultyIndex][bossIndex][slotIndex] = itemId
```

约束：

- `itemId` 必须是正整数。
- `difficultyIndex`、`bossIndex`、`slotIndex` 必须落在当前副本定义范围内。
- 与原版一致，不额外禁止玩家把相同物品放入多个心愿格；每个格子按原位置独立保存，但同一物品在一次掉落或拍卖事件中只触发一次提醒。
- 数据仅对当前登录角色可见，不通过插件消息或聊天发送。
- 不读取历史 BiaoGe 的 SavedVariables，也不迁移其历史数据。

现有平铺结构迁移仅处理已经写入 `BiaoGe.BGNext.wishlist` 的 BGNext 测试数据：只有能够从当前副本掉落表可靠确定难度和 Boss 的物品才迁移；无法归属的条目保留在隔离备份字段并提示用户，不静默猜测位置。

## 5. 导入与导出

导入和导出属于本人主动操作，不属于团队通信。

### 导出

- 点击原版位置的“导出心愿”后打开原版等效的小型文本窗口。
- 窗口展示将被复制的完整内容，自动全选但不自动复制、不发送。
- 文本只包含副本、难度、Boss、槽位顺序和物品 ID，不包含角色名、账号、聊天、时间、设备或其他记录。
- 空清单显示明确的空清单提示。

### 导入

- 点击原版位置的“导入心愿”后打开原版等效的小型多行输入窗口。
- 用户粘贴内容并主动点击确定或按 Enter 后才执行。
- 接受原版心愿文本的副本/难度/Boss/物品 ID 结构，以便迁移本人主动导出的清单；这不构成历史 SavedVariables 兼容。
- 严格校验副本、难度、Boss、槽位和物品 ID；忽略或拒绝越界字段，不执行 Lua、不解析聊天文本、不读取文件。
- 与原版一致，成功导入某副本前先替换该副本当前心愿；解析完全失败时不得清空现有清单。
- 完成后显示副本名称和实际导入装备数量。

导入/导出不新增游戏内插件消息，不扩大 BGLite 协议，也不产生游戏外自动传输。

## 6. 界面和交互验收

建立逐状态对照表，并在相同客户端、分辨率、UI 缩放、副本、难度和数据样例下保存原版 BiaoGe 与 BGNext 截图。至少核对：

- 主页签位置和宽度；
- 难度区块排列；
- Boss 名称、颜色和行距；
- 心愿列标题、格子尺寸和间距；
- 装备图标、链接截断和物品提示；
- 空格、已填、已掉落、鼠标悬浮、获得焦点和禁用状态；
- 右键删除、拖入、选择、Tab、方向键、Enter、Shift 和 Ctrl 交互；
- 导入/导出按钮和弹窗；
- 清空确认、导入成功、无效装备、无法归属和格子已满反馈；
- 掉落提醒及当前拍卖提醒。

仅以下差异可以接受：

1. 被本规格明确排除的团队传播与竞争查询功能；
2. 因客户端公开 API 不同而必须采用的等效降级；
3. 为说明本地隐私边界增加、且不挤占原版关键操作的简短提示；
4. 历史 BiaoGe 独占素材被权利清晰的等效素材替代。

其他差异必须修复，不能以“更简洁”“更现代”或“更好维护”为理由保留。

## 7. 架构与错误处理

- `Core/BGNext/Wishlist.lua` 负责验证、存储、查询、导入和导出纯逻辑。
- `Core/BGNext/WishlistUI.lua` 负责原版等效界面及用户输入，不自行承担持久化规则。
- 副本、难度、Boss 和掉落归属通过 BGLite 已有、经审查的本地数据库能力读取。
- 提醒适配放在独立边界中，只消费当前物品和本人心愿匹配结果。
- 任何无法确认副本或掉落归属的输入都拒绝写入。
- 模块异常只禁用心愿增强功能，不阻止 BGLite 基础拍卖与账单加载。
- 所有错误只在本地显示，不上传日志。

## 8. 测试与交付

实现必须采用测试先行，并至少覆盖：

- 有效和无效上下文；
- 难度、Boss、槽位边界；
- 正常掉落归属和无法归属；
- 添加、删除、去重、清空和列表压缩；
- 导出稳定性、空清单和字段最小化；
- 导入有效文本、部分无效、完全无效、越界、超量和替换语义；
- 本人角色隔离和其他副本隔离；
- 心愿掉落/拍卖匹配只产生本地提醒；
- 代码中不存在通报、竞争查询及新增消息发送路径；
- 各目标客户端的 API 降级；
- 原版/BGNext 同状态视觉与行为人工验收。

完成条件：自动化测试、BGLite 基线校验和 Lua 语法检查通过；游戏内原版对照表没有未说明差异；数据清单、PR 合规回答和已知限制已更新。未完成实机对照前，不得把心愿清单标记为完成。
