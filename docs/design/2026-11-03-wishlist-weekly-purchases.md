# 心愿部位浏览、时光服周常及本人拍卖记录

## 范围与设计

用户要求实现反馈中的功能，心愿入口明确为切换选项。保留默认按 Boss 查看；新增按部位浏览当前副本的正常直接掉落。选择部位后列出候选、Boss/难度及已选标记，通过现有 BG.SetHope 加入原来的心愿格，取消仍走原有删除入口。兑换物和无法判断部位的条目单独列出，不把成品兑换关系放宽为直接掉落。物品信息未缓存时保留待分类条目，接收物品缓存事件后只刷新可见窗口；离开/切换副本后的旧回调不得修改页面或心愿。

时光服角色总览增加团本周常及祖格周常，使用当前登录角色的任务完成标记和官方周重置时间。任何已知轮换任务交付为完成；全部可靠返回 false 才为未完成；证据不足为未知。只保存现有 activityStates 形状（status/observedAt/resetsAt），不保存任务日志、任务名、任务 ID 或其他玩家数据；旧记录无迁移。已有职业日常、金币、代币和其他版本族保持原有行为。任务变更事件和可见窗口到期维护复用已有机制。

拍卖记录已有“我买的”筛选。现有缓存表按角色名直接索引会漏掉带服务器名的买家。复用既有 PlayerIdentity 的完整身份比较，保留当前角色及原有同服已登录本人角色范围，仅筛选当前表中已有的成交记录，不新增历史保存、金额计算、自动捕获或通信。不把拍卖成交视作已经付款；原有交易状态和其他筛选保持不变。

## 参考研究与原创

官方 BGLite 2.4.4 仍作为上游参考；本次另只读研究用户提供的 BGLite 白云飞整合版 2.11.7。学到的用户可见行为是显示周常完成状态、按用途整理装备和本人记录。公开任务标识用于候选目录，不复制其算法、UI、结构、注释、文案、素材或持久化格式，不引入依赖。参考来源在维护文档如实记录，运行代码按 BGNext 自身接口独立实现。自动拾取开拍、自动心愿出价、跨团/跨角色商品档案和第三方协议不在本次范围。

## 数据与合规评估

必要性为当前玩家选心愿、查看本人周常及本人当前团成交。接收方仅本地 UI，无发送、外部目的地或导出。新增两项本人周常状态沿用本人快照覆盖和到期清理，关闭总览即停止采集；隐藏列和删除角色沿用现有控制。部位/视图选择及物品缓存标记仅在内存，不修改心愿存储结构；不保存全部候选装备快照。本人筛选只临时比较已有买家，禁止扩展为他人历史、跨团消费档案。失败处理为未知/待分类/不显示不匹配记录，绝不猜测身份、部位、周重置或成交状态。

## 实施与验收计划

1. 拍卖：先复现完整名与短名匹配差异，新增身份筛选失败用例，再接入真实筛选；验证同名异服隔离、其他状态不变。
2. 周常：先写目录/读取/重置/事件失败用例；逐步补全只读适配与视图。检查 API 缺失、异常、离线到期、隐藏和禁用、日常兼容及部分保存。
3. 心愿：先测试部位投影、直接掉落范围、重复和缓存缺失；实现独立候选浏览模块，在现有心愿页面添加视图切换；通过原入口增删，不迁移旧数据。验证跨副本、隐藏、缓存更新和已有心愿容量规则。
4. 补齐三语字符串、数据清单和未发布说明；逐个审核基线覆写。执行完整高风险门禁和适度独立审查，记录实机验证缺口。

本轮不承诺零回归，不将模拟测试表述成客户端实测；不自动安装或发布。
