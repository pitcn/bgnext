# 按客户端与专精生成装备过滤默认方案

日期：2026-08-31  
状态：已实施（自动化测试通过，待游戏内实机验证）
关联：GitHub Issue #22 的后续增强；实施前建立独立 enhancement Issue

## 目的

BGNext 当前内置装备过滤方案按职业生成。纯物理或纯法系职业尚可给出保守默认值，但德鲁伊、萨满、圣骑士和武僧等职业同时包含物理、法系、治疗或坦克玩法，职业级方案无法同时正确决定主属性、攻击强度、法术强度和坦克词缀。

默认方案改为按当前客户端实际存在的专精或旧式天赋树生成。玩家仍拥有完整的自定义能力；专精只提供更准确的默认配置，不成为绕过当前方案的隐藏过滤器。

## 研究与原创边界

本功能按 ADR-0003 执行。可以研究合法取得的 BGLite/BiaoGe 版本，重点确认原版按专精提供的默认装备过滤配置、玩家可见的方案组织方式、各客户端专精差异和兼容行为，也可以检查源码以理解版本判断与失败路径。

研究记录只保留插件与版本、行为事实、版本映射结论和 BGNext 需求。不得复制或机械改写第三方源码、数据表、名称、注释、UI 文案、图标、素材或导入格式。BGNext 的目录、适配器、状态模型、UI 和测试独立编写。

参考研究见 `docs/research/2026-08-31-biaoge-specialization-filter-reference.md`。BiaoGe 2.3.5 的默认方案证明了按职责／专精区分主属性、攻击强度、法术强度、治疗、坦克、武器和护甲的必要性；但它仍由玩家手动选择方案，旧天赋树并列时也可能得到不可靠结果。BGNext 只采用这些行为需求，不沿用其数据结构或选择逻辑。

## 核心选择

### 职业基础配置加专精覆盖

每个内置方案由两层合成：

1. **职业基础配置**：职业限制、可穿护甲、可用武器，以及全专精都明确一致的规则。
2. **专精覆盖配置**：允许的主属性、应过滤的攻击强度或法术强度、治疗／法力词缀、坦克词缀，以及专精名称与图标。

最终内置方案是一次确定性合成，不在过滤物品时临时猜职业或专精。过滤引擎仍只读取当前生效方案中的显式选项。

方案规则按装备需求建模，而不是为了 UI 对称而重复数据。两个专精若在某客户端拥有完全相同的装备需求，可以共享 BGNext 自有的覆盖规则构造器，但仍保留各自稳定的 `specKey`、名称和选择入口。任何不同的武器需求、主属性、物理／法术／治疗词缀或坦克规则都必须拆成独立覆盖。

### 版本化专精目录

目录键固定为 `clientFamily + classToken + specKey`，不能用一份跨版本通用的“第几个专精”表。

- 支持稳定专精 ID 的客户端：先读取当前专精索引，再通过暴雪接口解析稳定 spec ID；`specKey` 使用该 ID，不直接保存索引。
- 旧式天赋树客户端：读取当前激活天赋组，对该职业可用的天赋树比较已投入点数；`specKey` 使用客户端家族内稳定的 `classToken:tree:index`。
- 没有投入点数、最高点数并列、API 缺失或返回异常时：结果为未知，不猜测专精。
- 一个专精只有在该客户端家族的名称、图标、属性规则和暴雪 API 行为都完成记录后，才进入可自动选择目录。缺失目录不会用其他版本同名专精代替。

当前仓库已使用 `vanilla`、`tbc`、`titan`、`mop` 和 `retail` 等客户端家族；专精目录沿用同一隔离维度。实施研究必须逐家族确认实际 API 和专精集合，不能从正式服向旧版本倒推。

## 方案与跟随模式

装备过滤状态增加两种明确模式：

- **跟随当前专精**：新角色和执行“重置默认方案”后的默认模式。识别到受支持专精时，自动启用该专精的内置方案。
- **手动选择**：玩家选择任意自定义方案后进入此模式。后续切换专精不会覆盖玩家选择，直到玩家重新选择“跟随当前专精”。

专精或天赋变化事件只负责重新识别并选择目录中的内置方案，不修改自定义方案内容。跟随模式下暂时无法识别专精时，不清空、不创建猜测方案，也不改写保存值；界面显示“未识别当前专精，沿用当前方案”。首次使用即无法识别时，采用只含职业基础配置的保守方案。

已有角色升级时：

- 保留全部现有内置及自定义方案内容；
- 保留当前选择，并初始化为手动模式，避免更新后静默改变过滤结果；
- 玩家主动选择“跟随当前专精”或重置默认方案后，才启用新的专精默认值；
- 不读取或迁移历史 BiaoGe 装备过滤存档。

## UI 交互

方案选择器的第一个入口为“跟随当前专精”，并显示当前识别到的专精图标和名称。其后列出该角色的内置专精方案及自定义方案。

内置专精方案使用暴雪可用的专精名称与图标；API 无法提供时使用 BGNext 目录中已核验的本地名称和暴雪图标路径。未知专精显示明确状态，不展示错误图标或其他版本的占位方案。

“新建过滤方案”保持轻量：默认以当前生效方案作为一次性模板，预填当前专精图标，玩家编辑名称、图标和全部过滤选项。创建后得到普通自定义方案并切换到手动模式；它不会随专精模板后续变化，也不自动绑定某个专精。这样可以保持自定义方案可预测，并避免在创建窗口增加难以理解的绑定状态。

“重置”只重建当前客户端家族和职业的内置专精方案，并切回“跟随当前专精”；自定义方案不删除、不覆盖。

## 数据与事件

新增保存值只描述选择语义，不保存天赋点数或专精历史：

```lua
equipmentFilters[realmId][player] = {
    selectionMode = "follow-spec" | "manual",
    selectedId = "...",
    profiles = { ... },
    order = { ... },
}
```

`specKey` 只存在于内置目录和内置方案标识中。插件可以读取当前登录角色的职业、当前专精／天赋树及其变化事件；不检查其他玩家，不调用 `NotifyInspect`，不保存天赋点数，不发送插件消息或聊天，也不产生游戏外传输。

适配器合并短时间内重复的天赋／专精事件。只有解析出的 `specKey` 发生变化时才重新选择方案和刷新过滤结果，避免连续全表刷新。

## 模块边界

- `SpecializationAdapter`：将各客户端暴雪 API 结果转换为稳定 `specKey` 或未知状态。
- `EquipmentFilterSpecializations`：维护版本化专精目录，并将职业基础配置与专精覆盖合成为默认方案。
- `EquipmentFilter`：保存跟随／手动模式，执行迁移和方案选择；不包含客户端 API 分支。
- `EquipmentFilterUI`：展示模式、专精状态和方案，不自行推断专精。
- 现有过滤引擎：继续只执行生效方案，不新增职业或专精硬编码旁路。

## 失败处理

- 暴雪 API 缺失、报错或返回未知值：保守失败，不切换方案。
- 天赋点数并列或为零：报告未知，不以第一棵树作为默认。
- 目录缺少当前专精：保持现有方案，并在 UI 提示该客户端专精尚未建立默认值。
- 内置方案损坏：从当前客户端目录重建该内置方案；自定义方案不受影响。
- 保存值版本不支持：保留已有方案并进入手动模式，不静默删除。

## 测试与实机验证

自动化测试必须覆盖：

- 各客户端适配器的稳定 spec ID、旧式天赋树、双天赋组、零点、并列、API 缺失和异常返回；
- 职业基础配置与专精覆盖的确定性合成；
- 纯物理、纯法系、治疗、坦克和同职业不同专精的默认规则差异；
- 跟随模式切换、手动模式不切换、重新启用跟随和未知专精降级；
- 旧职业级方案迁移时不覆盖自定义内容；
- 重置只重建内置方案；
- 事件合并及 `specKey` 不变时不刷新；
- 无其他玩家检查、无通信、无新数据类别和发布包边界。

永久 60、周年 TBC、周年时光服、熊猫人和正式服必须分别记录为自动测试、模拟、实机验证或未验证。每个客户端至少完成：登录识别、切换专精／天赋组、跟随切换、手动方案保持、重载保存和代表性装备过滤。未完成对应客户端实机验证的专精目录不得宣称已验证支持。

## 非目标

- 根据装备、职责或当前拾取专精反向猜玩家玩法；
- 检查或保存其他玩家的专精；
- 自动修改自定义方案；
- 从历史 BiaoGe 存档导入过滤方案；
- 复制 BGLite/BiaoGe 的源码、数据表、UI 文案、图标素材或导入格式；
- 在本次改动中实现 Issue #28 的小地图悬停角色总览。
