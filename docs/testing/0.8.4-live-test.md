# BGNext 0.8.4 实机测试清单

## 安装

1. 完全退出游戏并备份 WTF。
2. 删除旧的 `BGNext` 和 `BGNext_Debug` 文件夹，不要覆盖安装。
3. 解压 `BGNext-0.8.4-LOCAL-DEBUG.zip`，把其中的 `BGNext` 和 `BGNext_Debug` 放入同一客户端的 `Interface/AddOns`。
4. 首轮只启用 BGNext 与 BGNext_Debug；第二轮再启用 NDUI 和日常插件组合。

## 每个客户端都要执行

依次输入：

```text
/bgndebug status
/bgndebug compat
/bgndebug all
```

反馈时保留三行完整输出。`status` 必须显示 `version=0.8.4`；`compat` 会显示当前客户端的 family、Interface 和 Build，并实际检查基础流程依赖的 API 与事件能否使用。

- `PASS`：已调用正式 BGNext 模块并核对明确业务结果。
- `FAIL`：当前客户端缺少 API/事件，或业务结果不符合预期；请停止该客户端发布并提供完整一行结果。
- `MANUAL`：该项必须观察真实界面、硬件输入或团队事件；不是失败，也不是自动通过。

永久 60、周年服、巫妖王、Titan、大地的裂变、MoP 和正式服必须分别留下结果；一个客户端的 PASS 不能代替其他客户端。

## 单人可完成

1. `/bgndebug accounting`：应 PASS，验证买家/金额预填、错买家拒绝、精确账单行与欠款分配。
2. `/bgndebug ledger`：应 PASS，验证主动采集、来源绑定、限量和直接换团边界状态机。
3. `/bgndebug auction`、`trade`、`mail`、`profession`：自动部分应 PASS，不会真实开拍、交易或发邮件。
4. `/bgndebug filter`：先完成内部模型检查，再按提示打开拍卖记录，切换法系/近战等方案，确认列表确实变化且没有全量显示。
5. `/bgndebug updatelog`：打开更新日志，滚动到 0.1.0，确认每一版文字完整、可滚动、没有被窗口截断。
6. `/bgndebug keyboard`：打开拍卖金额、欠款等输入框，关闭窗口后直接按移动键和聊天键；角色移动与键盘输入不能失效。
7. `/bgndebug ui`：依次查看主表、团长工具、待拍队列、拍卖中心、实收分金和更新日志；检查按钮重叠、文字越界、关闭按钮与不同 UI 缩放。
8. 完成后输入 `/bgndebug reset`，应显示 `PASS reset: debug-state-cleared`。

## 必须多人或真实环境验证

以下项目不能由单人 Debug Tool 自动宣称通过：

1. 团长/拾取职责刚变化后，第一条开拍、取消、暂停和恢复消息是否被其他成员接受。
2. 连续拍卖两件相同物品，不同买家与金额是否各自写入正确行。
3. 交易完成后，已付金额、剩余欠款、总消费和拍卖记录是否一致；取消交易不得记账。
4. 邮件真正发送成功后才生成记录；发送失败或取消不得推进下一人。
5. 对账播报期间普通成员进出不清空；来源离队、本人离团或直接换团会停止并清空。
6. Boss 原生拾取框及实际使用的第三方拾取框，只在团长或拾取职责下显示并能进入安全开拍流程。
7. 启用 NDUI 后重复键盘、拍卖窗口拖动、连续多拍和更新日志检查，BugSack 不应出现 BGNext 调用栈或受保护操作提示。

多人测试应记录：客户端、Interface、Build、BGNext 版本、插件组合、操作顺序、预期结果和实际结果；截图或错误日志需先删除无关玩家身份和聊天内容。
