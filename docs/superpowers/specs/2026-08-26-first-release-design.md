# BGNext 首版功能设计

## 目标

BGNext 首版以 BGLite 2.4.0 为运行基线，在不建立玩家历史画像、不扩大数据传播范围的前提下，恢复原版 BiaoGe 中已确认合规的个人辅助功能，并维持现有团队拍卖协议的兼容性。首个 BGNext 发布版本号为 `0.1.0`；界面不得把上游版本 `2.4.0` 显示成 BGNext 自身版本。

首版正式支持 `BGLite.toc` 当前声明的全部游戏接口版本。每个版本必须分别验证加载、界面、存档、团本识别、拍卖通信和降级行为；未完成验证的版本不得在 Release Notes 中标记为已验证。

## 来源与实现边界

- BGLite 代码是 BGNext 的可修改上游基线，可以直接维护和扩展。
- 原版 BiaoGe 用于确定获准恢复功能的可见效果、信息层级、布局关系、操作顺序和边界条件。
- BGNext 对非 BGLite 功能使用独立编写的 Lua 实现；不复制原版 BiaoGe 的独特代码结构、图片、声音、字体或其他未被单独确认可用的素材。
- 在合规功能范围内，界面入口、页签顺序、字段含义、控件尺寸与位置、快捷操作、状态变化、提示及完整使用流程必须逐项对照原版 BiaoGe，并以用户可感知效果一致为验收目标。
- “与原版一致”不表示恢复被本规格排除的数据处理或功能。其他玩家信息、跨团历史、隐藏代拍、卡秒狙击等红线行为必须删除或保持不可用，并在说明书和更新日志中披露差异。
- 不同游戏客户端因公开 API、系统字体或渲染比例产生不可避免的显示差异时，可以采用等效降级，但不得擅自重新设计功能或简化操作流程。
- 每个功能 Pull Request 必须附原版行为清单、原版与 BGNext 的同状态对照截图、BGNext 实现文件、数据范围、已知差异和测试证据。

## 项目身份与署名

- 插件作者显示为“国服社区共创”。
- 关于页面必须说明 BGNext 是独立、非官方社区项目。
- 感谢名单分别记录 BGLite 上游作者、原版 BiaoGe 功能参考来源、BGNext 代码贡献者、测试者、翻译者、设计贡献者和安全报告者。
- 上游或参考来源的致谢不表示相关人员参与、认可或负责 BGNext。
- 私下沟通、联系人和未公开材料不得写入仓库、插件界面或发布说明。

## 总体架构

新增功能放在独立的 `Core/BGNext/` 模块层，复用 BGLite 已有且合规的公共能力，不把新逻辑继续堆入大型核心文件。

计划模块：

- `About.lua`：关于、更新日志和感谢名单。
- `Wishlist.lua`：个人心愿清单及提醒。
- `EquipmentFilter.lua`：本人装备过滤。
- `CurrentShopping.lua`：当前团本个人购物清单。
- `OwnCharacters.lua`：自有角色总览。
- `AuctionPreset.lua`：拍卖价格预设。
- `AutoBid.lua`：受控自动出价。
- `CurrentTrade.lua`：最近一次团本的交易核对记录。
- `CurrentMail.lua`：最近一次团本的邮件核对记录。
- `DataLifecycle.lua`：当前团本数据生命周期、迁移和清理。
- `ConflictGuard.lua`：检测本机重复加载的表格/BGLite 系列插件并提供用户确认后的禁用操作。

每个业务功能模块具有独立初始化入口、启用开关和错误隔离。`DataLifecycle.lua` 与 `ConflictGuard.lua` 是不可绕过的安全模块，但其自身失败时仍不得阻止 BGLite 基础拍卖与账单界面加载。

## 界面结构

### 呼出命令与版本标识

- 主要呼出命令为 `/bgn`。
- 完整名称别名为 `/bgnext`。
- 继续接受 `/bglite` 作为不在说明书主命令区展示的旧版兼容别名，避免已有宏或用户习惯失效。
- 原有 `/gbg` 不再注册为 BGNext 命令；旧版兼容统一由 `/bglite` 提供。
- 命令匹配遵循游戏客户端既有的大小写处理方式，说明书统一使用小写形式。
- 主界面显示 `BGNext v0.1.0`；“基于 BGLite 2.4.0”作为独立的上游说明展示，不得混为同一版本号。

### 关于与社区入口

主界面提供三个小型入口：

1. 关于 BGNext；
2. 更新日志；
3. 感谢名单。

点击后在游戏内打开只读滚动面板，不自动打开网页，不发送数据。更新日志从随版本发布的本地静态内容读取；感谢名单从仓库维护的可审查静态数据生成。

现有 BGLite“纯净版说明”区域改写为 BGNext 说明书，至少包含：项目身份、上游基线、呼出命令、BGLite 混用范围、本地数据边界、最长七日的当前团结算规则、社区共创与贡献入口、非官方声明。不得在说明书中披露私下沟通内容或暗示官方背书。

### 熟悉度要求

首版合规功能按照原版对应功能的页签关系、栏目顺序、控件尺寸、按钮位置、操作流程和反馈状态逐项重建。现有自行设计的简化页面不视为完成。允许因安全说明、全版本适配或可访问性增加必要提示，但新增提示不得挤占、重排或改变原版关键操作。

每个界面必须建立视觉与行为验收表：在相同客户端、分辨率、UI 缩放、角色状态、副本和数据样例下分别截图原版 BiaoGe 与 BGNext，对照窗口位置、尺寸、页签、文字层级、装备格、按钮、颜色、禁用态、提示框和右键菜单。所有偏差必须修复，或在 Pull Request 中说明其对应的合规/API 限制。

### 本机重复加载保护

- 登录完成后检查本机实际启用或已加载的插件，不通过团队频道、密语或版本查询探测其他玩家。
- 团队中不同玩家分别使用 BGNext 与 BGLite 是正常兼容场景，不得触发冲突提示。
- 当同一客户端同时启用 BGNext 与另一个已知会共用 `BiaoGe` 存档入口、表格界面或相同拍卖处理器的插件时，每次登录会话最多提示一次。
- 提示框列出能够确认的冲突插件名称，并说明同时运行可能造成重复界面、重复消息、拍卖状态异常或存档冲突。
- 插件不得在无提示、无确认的情况下自动禁用其他插件或重载界面。
- 提供“只保留 BGNext 并重载”和“暂不处理”两个按钮。只有玩家点击前者后，才禁用本次明确检测到的其他插件并调用 `ReloadUI()`；任何识别不确定的插件不得自动纳入禁用列表。
- 已安装但未启用、未加载且不会参与当前会话的插件不触发提示。
- 检测属于尽力而为：必须覆盖仓库维护的已知插件身份及元数据特征，但不得宣称能够识别所有被改名或修改过的第三方分支。
- 提示文案采用：“检测到多个表格/BGLite 系列插件同时启用。它们可能共用存档入口和团队通信协议，同时运行可能造成重复界面、重复消息或拍卖状态异常。建议只启用 BGNext。”

## 功能设计

### 个人心愿清单

- 玩家只能为自己的角色设置心愿装备。
- 心愿按服务器、本人角色和副本保存。
- 恢复原版心愿页所在位置以及副本、难度、Boss 和装备格的组织方式，不采用独立的“输入物品 ID 列表”作为正式页面。
- 恢复原版的装备格录入、Alt/Shift 组合操作、右键取消、清空确认、已有心愿标记和相应提示；具体按键以原版实测行为清单为准，不凭记忆推断。
- 心愿装备在当前掉落或当前拍卖中出现时提供本地界面及声音提醒。
- 心愿内容不通过团队、密语或插件频道广播。
- 不提供心愿竞争查询、其他玩家心愿汇总或批量分享。

### 装备过滤

- 页面入口、开关位置、过滤分类、装备高亮/弱化样式、手动选择方式和刷新反馈必须与原版 BiaoGe 对应功能一致，不另行设计简化面板。
- 根据当前角色职业、专精、可用护甲类型、武器类型和物品元数据给出本地显示建议。
- 合适装备高亮，不合适装备弱化或折叠。
- 只有原版已经提供对应操作时，才保留手动覆盖或自定义方案；不得为了“增强”自行新增过滤规则编辑器。
- 过滤结果不评价其他玩家，也不向其他玩家发送。
- API 数据不足时显示“无法判断”，不得把推断伪装成确定结果。

### 当前团本个人购物清单

- 页面入口、栏目顺序、物品行、金额显示、合计区域、清空操作和购买后的刷新反馈必须与原版 BiaoGe 购物清单一致。
- 只汇总本人在当前一次团本购买的物品和金额。
- 不展示其他玩家的个人累计消费。
- 当前团本完成结算、玩家主动清空或开始新团后，旧数据删除或覆盖。
- 结算未完成时只允许暂存这一团，不形成历史列表、跨团搜索、趋势或累计统计。

### 当前团本交易与邮件核对

- 界面必须沿用原版对应功能的入口位置、窗口尺寸、栏目顺序、状态颜色、筛选/清空入口和核对操作；仅将名称明确标为“交易记录（当前团）”和“邮件记录（当前团）”。
- 原版中属于当前单团核对的行展示、物品提示、金额、时间、交易对象和完成状态保持一致；被移除的是跨团历史浏览和累计能力，不得用新的卡片、摘要页或不同工作流替代原版界面。
- 同一时间只保存当前或最近一次尚待核对的团本结算数据，不允许建立多个团本的历史列表。
- 最长保存时间为记录产生后的七个自然日；开始新的团本结算、用户主动清空或达到七日上限时，旧记录自动删除，以最先发生者为准。
- 交易记录仅保存结算必需的物品、金额、交易时间、交易状态和相关角色名。
- 邮件记录仅保存结算必需的物品、金额、发送或接收时间、处理状态和相关角色名；不保存邮件正文及与当前团本结算无关的主题、附件或私人邮件。
- 不按玩家汇总次数、金额或行为，不提供跨团搜索、累计统计、排名和玩家档案。
- 数据仅保存在本地，不通过插件频道广播，也不上传到游戏外。
- 无法可靠判断记录是否属于当前团本结算时，不纳入该记录。

### 自有角色总览

- 页面入口、固定窗口、栏目顺序、角色排序、装备概况、团本锁定展示、鼠标提示和右键删除习惯必须与原版 BiaoGe 自有角色总览一致。
- 只记录当前账号中由玩家本人实际登录过的角色。
- 展示角色名、服务器、职业、等级、装备概况和团本锁定状态。
- 数据仅保存在玩家本地，不广播、不上传、不供其他玩家查询。
- 不允许通过点击其他玩家建立或查看其角色档案。
- 每个角色提供明确的本地删除入口。

### 拍卖价格预设

- 页面入口、预设列表、编辑框、按钮位置、启用方式、当前预设提示及应用到拍卖窗口的流程必须与原版 BiaoGe 拍卖预设一致。
- 保存玩家自己的常用加价步进和心理最高价。
- 预设仅在玩家主动选择时应用到当前拍卖。
- 当前使用的步进、最高价和下一次可能出价必须在界面中可见。
- 不根据其他玩家的历史出价、消费或装备情况生成价格。

### 受控自动出价

自动出价只负责当前一件拍卖物品，复用 BGLite 当前拍卖协议发送普通出价，不新增用于收集玩家数据的协议。

当前拍卖窗口中的启用入口、最高价输入、加价显示、出价反馈、取消入口和拍卖结束反馈必须与原版 BiaoGe 允许保留的自动出价流程一致。BGNext 只增加不会改变主流程的安全停止提示；不得把它改造成独立设置页或不同的竞价交互。

状态机：

1. `IDLE`：未启用；
2. `ARMED`：玩家为当前拍卖明确启用并确认最高价；
3. `WAITING`：等待当前拍卖的新有效价格；
4. `BID_PENDING`：已计算下一口价格，等待执行；
5. `BID_SENT`：通过现有协议发送一口普通出价；
6. 返回 `WAITING`，或进入 `STOPPED`。

以下任一条件必须进入 `STOPPED`：

- 用户取消；
- 当前拍卖结束、撤回或切换物品；
- 下一口超过最高价；
- 玩家离团、掉线、重新加载界面或退出游戏；
- 拍卖协议状态不一致；
- 输入价格无效、加价规则无法确定或发送失败；
- 模块被禁用。

自动出价启用状态不写入 SavedVariables，不跨拍卖、不跨登录、不离线运行。界面必须持续显示启用状态、最高价和停止按钮。首版不实现隐藏卡秒、随机化规避、后台代拍或无人值守竞价。

## 数据模型

新增数据统一存放在现有本地存档入口下的独立命名空间：

```lua
BiaoGe.BGNext = {
    schemaVersion = 1,
    settings = {},
    wishlist = {},
    equipmentFilters = {},
    ownCharacters = {},
    currentRaid = {},
    currentSettlement = {
        raidId = nil,
        expiresAt = nil,
        trades = {},
        mails = {},
    },
    auctionPresets = {},
}
```

自动出价运行状态只存在于内存，不进入上述表。

迁移过程只读取实现首版功能所需且属于玩家本人的兼容数据。长期历史团本、跨团交易和邮件历史、其他玩家画像、评分、举报和黑名单数据不迁移到 `BiaoGe.BGNext`。现有交易或邮件数据只有在能够确认属于最近一次待结算团本、字段满足最小必要要求且尚未超过七日上限时，才可迁移到唯一的 `currentSettlement`；否则保持原数据不动且不再读取。

## 历史数据处理

- 停止历史表格继续记录或展示跨团数据。
- 将现有交易历史和邮件历史入口改造成仅服务于最近一次团本、最长保存七日的当前结算记录，不保留跨团查询能力。
- 停止其他玩家历史记录的读取、搜索、关联和汇总。
- 不在升级时静默删除用户已有旧数据，避免不可逆数据损失和影响其他插件。
- 提供明确说明范围的手动清理入口；执行清理前要求用户确认。
- 清理功能只能删除 BGNext 明确列出的目标字段，不得递归删除整个 `BiaoGe` 存档表。
- `currentSettlement` 只允许存在一组数据；开始新团、主动清空或到达 `expiresAt` 时必须原子化清除物品、金额、角色名和状态字段。

## 协议兼容

- 保留 BGLite 必需的插件目录、SavedVariables 入口、公开聊天格式和当前拍卖协议标识。
- BGNext 与 BGLite 混用时，基础拍卖、出价、状态更新和结束流程必须可互通。
- BGNext 增强功能不得要求 BGLite 用户安装新协议才能参加基础拍卖。
- 暂不承诺与历史 BiaoGe 插件兼容，也不自动导入其历史数据。
- 未知版本或未知协议消息必须安全忽略，不得导致自动出价或数据写入。

## 全版本支持

首版覆盖 `BGLite.toc` 当前声明的全部接口版本。实现时通过版本适配层隔离 API 差异，功能模块不得散落大量客户端版本判断。

最低验证项：

- 插件加载且无 Lua 错误；
- 主界面与新增页签可打开、关闭和缩放；
- 本地存档可写入、重载和删除；
- 副本、难度和锁定状态识别正确；
- 心愿提醒与装备过滤不会因缺失 API 中断；
- 当前团本购物清单正确重置；
- 当前结算交易和邮件记录在新团开始、主动清空和七日到期时正确删除；
- 与同版本 BGLite 完成拍卖互通；
- 自动出价在所有停止条件下可靠终止；
- 不支持的单项能力能够明确降级而不是静默报错。

无法取得某一客户端实机环境时，Release Notes 必须区分“代码兼容”“模拟验证”和“实机验证”，不得笼统宣称全部实机通过。

## 错误处理与安全降级

- 所有自动化默认关闭。
- 无法确认数据归属时不保存。
- 无法确认当前团本身份时不继承已有购物数据。
- 无法确认拍卖状态时立即停止自动出价。
- 模块初始化失败时记录脱敏的本地错误并禁用该模块，不上传日志。
- 所有清理、导出和代表玩家执行的操作必须提供取消路径。

## 测试策略

- 为数据生命周期、角色归属判断、价格计算和自动出价状态机编写可重复的 Lua 单元测试或独立测试夹具。
- 为 BGLite 与 BGNext 混用建立协议样例和回归测试。
- 对每个支持的游戏版本建立兼容矩阵。
- 手工测试重点覆盖界面习惯、重载、断线、离团、拍卖切换、价格越界和模块禁用。
- 为每个恢复界面保存原版与 BGNext 的同状态对照截图和行为检查表；未完成对照的功能不得标记为完成。
- 命令测试必须覆盖 `/bgn`、`/bgnext` 和兼容别名 `/bglite`，并确认说明书只推荐前两者。
- 重复加载测试必须覆盖：仅 BGNext、BGNext 与已禁用插件、BGNext 与一个已知冲突插件、多个已知冲突插件、用户取消、用户确认禁用并重载，以及团队成员使用不同版本但本机无重复插件。
- 基线检查继续验证未声明修改的 BGLite 文件；所有必要的上游文件改动进入明确覆盖清单并在 Pull Request 中解释。

## 首版不包含

- 历史团本、历史账单或跨团累计统计；
- 其他玩家角色总览、画像、评价、排名或长期记录；
- 跨团或长期交易历史、邮件历史、举报档案和黑名单恢复；
- 心愿分享、心愿竞争查询或其他玩家需求统计；
- 游戏外自动上传、遥测、云同步或远程日志；
- 原版 BiaoGe 数据兼容及历史导入；
- 隐藏卡秒、离线代拍、跨拍卖后台自动出价；
- 权利状态不清晰的第三方代码和视觉素材。

## 首版验收条件

1. 十一个计划模块均可独立初始化；九个用户功能模块可以单独启用和禁用。数据生命周期模块作为所有记录型模块的强制依赖，重复加载保护作为本机冲突防护，两者均不允许由普通功能开关绕过。
2. 关于、更新日志和感谢名单内容完整且来源可审查。
3. 心愿、过滤、购物清单和角色总览严格遵守本人或当前单团范围。
4. 自动出价的每个停止条件均有测试证据。
5. BGNext 与 BGLite 基础拍卖互通测试通过。
6. 所有声明支持的游戏版本都有明确验证状态。
7. 没有新增游戏外通信、遥测或隐藏数据传输。
8. 历史表格不再继续记录或提供入口；交易和邮件只保留最近一次团本、最长七日的当前结算记录。
9. Release Notes 完整披露数据范围、兼容状态、已知问题和贡献者。
