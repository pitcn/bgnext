# 角色总览自定义角色顺序设计

## 目标

在“设置 → 角色总览”中允许玩家使用按钮调整角色行顺序。功能保持简单，不增加拖拽、分组、自动排序规则或独立管理窗口，也不改变角色快照的内容和采集流程。

## 当前行为

角色总览当前使用固定顺序：当前服务器优先，其后按服务器 ID 和角色名排列。该规则继续作为未自定义时的默认顺序，也作为无效排序数据的安全回退。

## 交互

角色总览设置页新增“角色顺序”区域，列出当前客户端版本已经保存的角色。每行显示角色名；跨服务器同名时同时显示足以区分的短服务器名。

每行只提供两个操作按钮：

- “上移”：与当前列表中的上一名交换；已位于第一名时禁用。
- “下移”：与当前列表中的下一名交换；已位于最后一名时禁用。

列表下方提供“恢复默认排序”。该操作只清除当前客户端版本的自定义顺序，立即恢复现有固定规则，不删除任何角色快照。移动和恢复操作立即刷新已打开的角色总览。

不实现拖拽、置顶、按职业/装等/更新时间排序、服务器分组开关或跨账号同步。

## 顺序范围

顺序按客户端版本族分别保存。例如熊猫人、泰坦和正式服互不影响。

同一版本内使用一份跨服务器顺序。角色身份使用现有的 `realmId + player`，不能只用角色名；这样同名跨服务器角色仍可独立移动。角色总览切换“当前服务器/全部服务器”时，只投影当前可见角色，但保持它们在完整自定义顺序中的相对次序。

新发现且尚未出现在自定义顺序中的角色按现有默认规则追加到已排序角色之后。删除角色时不要求重写其他角色快照；排序读取会忽略已经不存在的身份，保存下一次移动结果时清理失效项。清空当前版本或全部角色数据时，对应自定义顺序一并清除，避免留下无意义标识。

## 数据模型

在 `BiaoGe.BGNext` 下新增：

```text
roleOverviewCharacterOrder[clientFamily] = {
  { realmId = number, player = string },
  ...
}
```

只接受已支持客户端版本族、数值服务器 ID、非空角色名和无重复身份。读取前重建并校验数据；错误类型、重复项和不存在的角色均被忽略，不得引发 Lua 错误。功能不增加时间、职业、装备、团本进度、账号标识、通信或游戏外数据。

实现时同步更新 `docs/security/data-inventory.md`。现有 `schemaVersion = 1` 不因可选字段增加而迁移；缺少字段等同于从未自定义。

## 模块边界

- `OwnCharacters` 继续拥有角色快照，并新增纯 Lua 的顺序读取、移动、重置和清理函数。
- `OwnCharactersView` 只接收已经校验的顺序，并在投影行时应用；无顺序或顺序异常时完全沿用当前默认排序。
- `RoleOverviewSettings` 只渲染列表和调用模型函数，不直接遍历或改写 SavedVariables。
- `OwnCharactersRuntime`、版本适配器、采集器和角色总览主窗口不新增事件或通信。

不修改 BGLite 基线文件，不参考或复制第三方插件实现。

## 错误与兼容处理

- 无角色数据时显示简短空态，移动按钮不出现。
- 一个角色时两个移动按钮均禁用。
- 任何损坏、旧格式或重复排序值都按“有效项优先、其余角色默认追加”处理。
- 当前版本不支持角色总览时，不显示排序区域。
- 功能关闭时保留用户顺序；重新启用后继续生效。
- 旧用户没有新字段，界面顺序必须与 0.8.5 完全一致。

## 验收与测试

自动化测试至少覆盖：

1. 无自定义数据时保持当前服务器优先、服务器 ID、角色名的既有顺序。
2. 上移、下移的边界和连续移动结果正确，并且不改变角色快照。
3. 熊猫人、泰坦和正式服的顺序互不影响。
4. 同名跨服务器角色使用完整身份独立排序。
5. “当前服务器”和“全部服务器”视图保持自定义相对顺序。
6. 新角色按默认规则追加；失效、重复和损坏项安全忽略并在下次保存时清理。
7. 删除单个角色、清空当前版本、清空全部数据时清理对应顺序。
8. 恢复默认排序只清除排序设置并立即刷新，不删除角色数据。
9. 设置页首尾按钮禁用状态、空态和跨服务器标签正确。
10. 原有角色采集、栏目设置、右键删除、窗口布局和多客户端测试保持通过。

实机只需在一个支持角色总览的客户端确认：设置页按钮可用、顺序即时刷新、`/reload` 后保留、恢复默认有效。其他客户端由隔离数据和自动化测试覆盖，不能把单客户端实测描述成全版本实测。
