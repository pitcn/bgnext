# BGNext 时光服角色总览首版收口设计

日期：2026-08-27  
状态：维护者已确认，待实施计划

## 1. 目标与发布范围

首个社区版本只把周年时光服角色总览标记为“已支持”。经典永久 60、探索赛季、TBC、巫妖王、大地的裂变、熊猫人和正式服继续保留版本适配器边界，但在各自目录、API、自动化测试和实机证据补齐前，不显示合并副本或通用货币等不可靠占位，也不对外宣称已经支持。

本阶段完成以下时光服行为：

- 每个团本实例使用独立实例 ID 和独立列，禁止把两个副本合成一列；
- 保持角色为行、团本/装备/货币为列的表格结构；
- 物品图标显示官方物品提示；
- 货币表头只显示官方图标，悬停显示完整名称；
- 装备列和数值列按内容动态计算宽度，禁止数字粘连或图标溢出；
- 固定窗口保留表头加号进入设置页，由设置页统一隐藏或恢复列。

## 2. 客户端能力边界

角色总览使用共享模型、投影和渲染器，但每个客户端版本族必须由独立目录声明能力。目录至少声明：

- 独立的团本实例 ID、短标题、完整名称和默认显示状态；
- 可用装备分类、受监控物品、货币、专业和其他资源；
- 每个字段使用的暴雪 API、不可用时的安全降级和验证状态；
- `code-covered`、`automatically-tested`、`simulated`、`tested-in-game` 或 `unverified` 状态。

首版仅时光服目录可以达到 `tested-in-game`。其他版本不复用时光服货币，不使用“P1三本”“海山黑庙”“毒蛇风暴”等把不同实例 ID 合并起来的占位列。当前客户端没有已验证目录时，角色总览保持可加载并显示“该版本适配中”，不得渲染假数据。

## 3. 时光服团本列

默认目录中的每一列对应一个实际实例：太阳之井、祖阿曼、十字军的试炼、祖尔格拉布、纳克萨玛斯、黑曜石圣殿、永恒之眼、毒蛇神殿、风暴要塞、熔火之心和阿尔卡冯的宝库。世界 Boss 独立声明，不与团队副本合并。

默认可见列继续使用维护者确认的短标题，例如 `SW`、`ZAM`、`TOC`、`ZG`、`NAXX`、`MC` 和“宝库”。悬停表头时显示完整副本名称及可用的难度、进度和重置说明。

## 4. 装备与受监控物品

默认摘要只展示主专业、武器、饰品、已有橙装、升级物品及已确认的时光服资源。完整装备仍作为默认隐藏的“装备详情”列，由用户主动开启。

每个装备或受监控物品图标必须保留可解析的物品链接或物品 ID：

- 有物品链接时使用暴雪 `GameTooltip:SetHyperlink`；
- 只有物品 ID 时使用客户端可用的官方物品提示 API；
- 物品数据尚未缓存时先请求加载，当前悬停不抛错，数据到达后允许刷新；
- 鼠标离开图标时关闭提示；
- 不自行拼接装备属性、评分或适用性结论。

装备类列的宽度由当前可见角色中该列最大图标数量计算，并预留图标间距。没有物品时保留最小列宽，但不显示伪造图标。

## 5. 货币表头与数值布局

所有货币列的表头只显示暴雪返回的货币图标。鼠标悬停图标时显示完整本地化名称；API 暂时无结果时使用时光服目录中的明确名称作为后备，不显示错误货币。

货币数值列宽由表头图标最小宽度、所有角色数值和合计值的实际文本宽度共同决定。相邻列之间保留固定间距，确保五位以上数值和合计行不会粘连。金币保持金币语义和格式，不当作普通货币 ID。

## 6. 列显示设置

固定窗口不提供表头 `×`。列的隐藏与恢复统一由设置页处理，避免悬停控件遮挡紧凑表头或造成误操作。

每个分区表头行最右侧显示一个 `+`：

- 点击后打开 BGNext 设置中的角色总览对应分区；
- 设置页保留全部可用列的复选框；
- 所有可选列都可以在设置页关闭或重新开启；
- “恢复当前版本默认列”只重置显示偏好，不清理角色数据；
- 临时悬停预览不显示可点击 `×`，避免误操作。

## 7. 数据、安全与来源

本阶段不增加新的持久数据类别。继续只使用 `BiaoGe.BGNext.ownCharacters` 最近快照和现有的 `roleOverviewColumns[clientFamily]` 显示偏好。

- 只读取当前登录角色；
- 不读取或显示其他玩家；
- 不增加插件通信、聊天发送、上传、遥测或导出；
- 不建立装备、货币或团本历史；
- 不复制、改写或转换 BiaoGe 及社区插件代码或素材；
- 用户可见习惯仅作为产品规格，运行实现继续基于 BGLite、暴雪 API 和 BGNext 原创代码。

## 8. 测试与验收

自动化测试必须先失败再实现，并至少覆盖：

1. 非时光服的未验证目录不会输出合并副本或错误货币列；
2. 时光服每个团本列只有一个独立实例 ID；
3. 物品单元格投影保留 Tooltip 所需的链接或 ID；
4. 装备列宽随最大图标数量增长；
5. 数值列宽考虑角色值和合计值，并保留列间距；
6. 货币表头模型包含官方图标和完整名称；
7. 设置页隐藏列只改变当前版本的显示设置，不删除快照；
8. `+` 打开正确设置分区；悬停预览不允许表头删除操作；
9. 源码中不存在新增通信或外部传输调用。

游戏内验收至少包括：

- 所有时光服团本独立显示且名称、短标题、进度正确；
- 武器、饰品、橙装和升级物品悬停出现暴雪官方完整物品提示；
- 货币表头仅图标，悬停显示完整名称；
- 多件橙装/升级物品时图标不溢出；
- 大数值和合计行不重叠；
- 分区 `+`、设置页隐藏/恢复及窗口即时重排正常；
- 临时预览层级、固定窗口位置和 BGLite 主界面入口正常。

没有对应客户端实机证据的版本继续标记 `unverified`，不能因为 Lua 测试通过而升级为“支持”。

## 9. 实施顺序

1. 先移除或隔离非时光服的不可靠占位目录，并增加明确支持状态；
2. 再完成时光服列模型、Tooltip 数据和动态宽度测试；
3. 实现货币图标表头、物品 Tooltip 和分区 `+`；
4. 执行完整 Lua、基线、隐私与差异检查；
5. 安装到时光服客户端进行截图和交互验收；
6. 时光服验收完成后，另行设计并逐版本接入其他目录。
