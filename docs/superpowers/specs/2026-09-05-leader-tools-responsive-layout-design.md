# 团长工具响应式布局设计

## 背景与目标

0.8.0 的团长工具以 680×470 固定窗口和逐控件绝对坐标组织四个页面。在部分 UI 缩放下，支出模板底部按钮越界，拍卖中心筛选按钮与说明文字重叠，实收与分金的确认按钮压住说明。此次只修布局，不改变模板、历史、拍卖或结算业务行为。

## 方案比较

### A. 逐页微调坐标

改动最少，但仍依赖固定坐标；简中长文案或 UI 缩放变化后容易再次重叠，不采用。

### B. 单纯增大固定窗口

内部空间充足，但高 UI 缩放或窄屏下窗口会超出屏幕，不采用。

### C. 逻辑画布、共享区域与屏幕适配 — 采用

使用 720×500 的稳定逻辑画布，根据 `UIParent` 可用宽高只向下缩放。四页统一划分为页头、主体和底部操作区，各页通过锚点填充这些区域。此方案既保留可预测的布局，又能在窄屏和高 UI 缩放下完整留在屏幕内。

## 布局

- 窗口逻辑尺寸为 720×500，四周保留 16 像素屏幕安全边距；缩放上限为 1，下限为 0.70。
- 标题与关闭按钮位于固定页头；四个标签按钮在标题下方横向排列。
- 内容区从标签下方延伸到底部内边距，页面不得把控件锚定到内容区之外。
- 支出模板：左侧模板列表，右侧名称和多行编辑区；状态行与两排操作按钮自底部向上锚定，编辑区填充其余空间。
- 成交摘要：摘要与筛选在顶部，操作条在底部，多行结果区锚定在两者之间。
- 拍卖中心：筛选按钮单独占第一行，风险提示单独占第二行；拍品列表位于下方滚动区，最多保留 20 个运行时行。
- 实收与分金：确认按钮与说明放入底部操作区，摘要文本只使用其上方区域并允许自动换行。

## 组件边界

新增纯 Lua 布局模块 `LeaderToolsLayout`，只提供尺寸、间距、缩放和可见行数计算；`LeaderToolsUI` 消费这些值创建游戏控件。布局模块不访问 SavedVariables、不注册事件、不执行通信。现有 Store、View、Runtime 接口保持不变。

## 失败处理

- 无法读取父窗口尺寸时使用 1.0 缩放。
- 父窗口过小时缩放不低于 0.70，配合 `SetClampedToScreen` 保证关闭按钮可找回；低于该可用尺寸不承诺舒适阅读，但不得产生 Lua 错误。
- 滚动 API 缺失的测试环境中，几何计算仍可独立验证；游戏内使用原生 ScrollFrame。

## 验证

- 先为 720×500、常见窄屏和高 UI 缩放输入编写纯几何 RED 测试，检查各区域不交叠且不越界。
- fake-widget 测试加载真实 `LeaderToolsUI`，验证窗口尺寸、缩放刷新、关闭按钮、四页锚点和拍卖滚动区。
- 运行全套 Lua 测试、基准校验、全部 Lua 语法检查和 `git diff --check`。
- 实机复验仍保留为人工项：四页逐页截图，至少覆盖用户反馈时的 UI 缩放。

## 明确不做

- 不改页面业务逻辑、数据结构、保留周期、拍卖权限或结算规则。
- 不新增 SavedVariables、插件通信、聊天、交易或邮件采集。
- 不重做视觉主题；本 issue 只处理空间、锚点、滚动和屏幕适配。
