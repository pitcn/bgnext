# 待拍队列 UI 改造设计（Issue #80）

## 目标

在不改变队列、定价和拍卖协议的前提下，把待拍队列改成与 BGNext 主界面一致的紧凑工具窗口。窗口必须容易关闭、空状态清楚、多件装备时不超出屏幕，并防止误清空。

## 布局

- 使用 `BG.CreateMainFrame` 提供统一标题栏、边框和右上角关闭按钮。
- 固定宽度 420；高度随条目数增长，并按屏幕高度限制可见行数。
- 顶部显示队列计数、装备链接输入框和“添加”。
- 每行显示装备、数量、价格来源，以及数量、排序、移除操作。
- 底部保留滚动按钮、操作提示和“清空队列”。
- 空队列显示加入方式，不保留大片空白区域。

## 交互约束

- 关闭窗口只隐藏窗口，不清空队列。
- 清空队列必须经过二次确认，并明确说明关闭窗口不会清空。
- 单击装备仍进入现有的价格确认和开拍流程；不新增自动连拍行为。
- 不新增 SavedVariables、聊天通信、团队同步或长期数据。

## 验证

- 自动测试覆盖自适应尺寸、共享窗口外壳、关闭行为和清空确认。
- 三种语言均提供新增文案。
- 实机检查留给合并前人工验证：缩放、长装备名、长英文文案及不同分辨率。
