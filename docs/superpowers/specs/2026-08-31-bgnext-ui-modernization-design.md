# BGNext 全局 UI 现代化设计

## 目标

在不破坏已发布插件稳定性、原版 BiaoGe 账单肌肉记忆和整页截图用途的前提下，为 BGNext 建立一致、原创、可跨客户端降级的视觉与交互体系。

本设计覆盖整个插件，但不要求所有页面使用相同布局。团队账单是受保护的兼容界面；角色总览、装备过滤、价格预设、心愿清单和设置等非账单页面可以重新组织导航与信息层级。

## 已确认的产品决策

1. 采用“统一视觉，同时优化非账单页面导航与信息层级”的方向。
2. 主账单保留原版 BiaoGe 的元素位置、尺寸、分栏、Boss 分区、行列容量、底部操作区、交互方式和整页截图构图，只更新表面样式。
3. 账单必须继续承载大型团本约 100 件装备，不能改成需要分页、纵向长滚动或多张截图的普通管理表格。
4. 视觉识别来自 BGNext 当前 Logo：深海军蓝为背景体系，金色用于品牌和关键操作，亮青色用于选中、焦点、悬停与链接。
5. 新 UI 首先作为可切换的预览外观发布，经典外观保留一到两个版本；完成游戏内验证后再决定是否默认启用。
6. 第一轮采用“设计系统 + 主账单兼容换肤”，不同时重构非账单页面；价格预设等未完成开发与本轮 UI 工作保持独立。
7. 第一轮视觉方向采用“平衡品牌”：现代感来自半透明层级、细边框、对齐和完整控件状态，不使用大面积发光、过度渐变或堆叠卡片制造现代感。
8. 主账单必须继续半透明显示，使玩家在大屏打开表格时仍能观察战场。58% 是预览主题的设计参考值，不覆盖老玩家已有透明度设置。
9. 第一轮只通过覆盖式换肤层修改既有控件外观，不替换控件，不接管事件，不建立第二套账单界面。
10. 首个预览版本对新老玩家均默认经典主题；只有用户主动选择后才保存预览主题偏好。

## 参考研究与原创边界

研究对象为本机合法安装的 EllesmereUI 9.0.8。其许可将除第三方资源之外的内容标记为版权所有、保留所有未明确授予的权利。

本设计只提取以下玩家可见原则：

- 深色中性背景上的清晰层级；
- 克制且一致的品牌强调色；
- 统一的按钮、输入框、选择状态、提示框和弹窗反馈；
- 设置类页面使用清晰导航与分组；
- 悬停、按下、禁用和焦点状态可以立即辨认。

BGNext 不复制、翻译、改写、移植或打包 EllesmereUI 的源码、内部结构、标识符、文案、字体、图标、纹理、声音、布局成品或其他资产。实现使用 BGNext 自有模块边界、Blizzard API 和自行制作或已有授权资源。研究记录遵守 ADR-0003。

## 信息架构

### 受保护的团队账单

团队账单继续采用现有 BiaoGe 布局。以下内容构成几何兼容契约：

- 团本页签和 Boss／区域分区；
- 装备、买家、金额字段的位置与编辑方式；
- 每个分区的行数、列数与总体容量；
- 杂项、罚款、补贴、总览和工资区的位置；
- 底部功能入口和主要操作的位置；
- 窗口尺寸、截图边界及一张图包含完整账单的能力。

允许变化的内容仅限：

- 背景、边框、分隔线和阴影；
- 字体选择、抗锯齿与颜色，但不得导致文本截断或布局位移；
- 按钮、输入框和页签的默认、悬停、按下、选中、禁用与焦点样式；
- BGNext Logo 和版本标识；
- 不改变几何结构的可选截图净化状态，例如隐藏纯装饰性控件。

### 允许重构的非账单页面

角色总览、装备过滤、价格预设、心愿清单、导入导出和设置页面可以使用统一的 BGNext 工作台外壳：

- 一级导航按“团队准备、角色与账号、设置”分组；
- 页面内部使用二级页签、分段标题或卡片表达局部任务；
- 高频动作靠近内容，危险动作与主动作在位置和颜色上明确区分；
- 大数据列表支持搜索、筛选、空状态和加载状态；
- 窄屏优先收起辅助信息，不隐藏核心操作。

拍卖窗口保持现有操作顺序和权限语义，可以优化状态反馈、错误提示和控件外观，但不能因美化改变开拍流程或消息协议。

## 视觉系统

### 品牌颜色

已从仓库当前 `Media/icon/BGNext-256.png` 提取第一阶段品牌基准色：

- 深海军蓝 `#010F23`：窗口背景基色；
- 窗口表面 `#07182A`：主半透明表面；
- 抬升表面 `#0C2033`：标题、输入框和局部高对比表面；
- Logo 金 `#F5B230`：品牌、关键数字和唯一主要操作；
- 箭头青 `#00E6FF`：当前页、焦点、悬停、链接和选择状态；仅用于文字或 1–2 像素强调线，不铺设大面积高饱和色块；
- 主要文字 `#E8F1F8`，次要文字使用降低亮度的蓝灰色；
- 红、绿、橙：仅用于错误、成功和警告，不与品牌色混用；
- 装备品质色、职业色和现有业务状态色继续保持其游戏语义。

最终游戏内色值允许为可读性做小幅校准，但不得改变上述语义关系。任何校准都需在相同游戏场景、分辨率和透明度下保留前后截图。

### 第一阶段视觉原则

- 主窗口沿用玩家当前透明度；设计稿以约 58% 不透明度验证战场可见性。局部标题、输入框和汇总区域可比主表面高 10–18 个百分点，但不能形成遮挡战场的大块实色背景。
- 现代感优先来自信息层级、对齐、细分隔线和状态一致性。账单兼容密度下不新增外边距、不扩大控件、不依赖圆角卡片。
- 金色保持稀缺：同一操作区最多一个金色主要操作；普通按钮使用深色表面，危险操作使用克制红色。
- 青色保持克制：用于当前页下划线、输入焦点、悬停边框和链接，不与装备精良品质色混为大面积背景。
- 第一阶段继续使用客户端可用字体和既有资源，不新增字体、阴影素材、模糊资源或持续动画。高级感不能依赖跨客户端不稳定能力。
- 行悬停只改变已存在纹理的颜色或透明度；不得在悬停时创建新对象。

### 设计令牌

建立统一令牌而不是在各页面散落数值：

- 背景、表面、边框、文字、强调和状态颜色；
- 正文字号、标题字号、数字字号和字体降级链；
- 控件高度、内边距、分组间距和分隔线；非账单页面未来可定义圆角，但账单兼容主题不依赖新增圆角资源；
- 悬停、按下、选中、禁用、焦点和错误状态；
- 普通、紧凑和账单兼容三种密度规则。

### 组件

统一组件至少包括：按钮、图标按钮、页签、输入框、搜索框、复选框、单选项、开关、下拉菜单、滚动容器、提示框、确认弹窗、状态标签、空状态、分段标题和列表行。

组件必须复用纹理和 FontString，不得因每次悬停或刷新反复创建对象。字体或资源加载失败时使用客户端内置资源并保持可操作。

## 技术边界

建议使用三个职责清晰的层次：

1. `UITheme`：提供设计令牌、字体／资源降级和通用组件状态，不包含业务逻辑。
2. `LegacyLedgerSkin`：把主题投影到现有账单控件，不负责创建或重新定位账单结构。
3. `WorkspaceUI`：为非账单页面提供新的导航外壳和页面组件。

第一阶段只实现前两个层次。`WorkspaceUI` 属于第二阶段，不得为了提前展示完整新 UI 而混入第一阶段提交。

### 覆盖式换肤契约

`LegacyLedgerSkin` 在既有账单控件创建完成后运行。它可以修改：

- 背景纹理、颜色和透明度；
- 边框、分隔线及已有阴影的显示属性；
- FontObject、字体颜色和不改变测量结果的描边标志；
- 已有按钮、页签和输入框的默认、悬停、按下、选中、禁用、焦点与错误样式。

它禁止调用或替换以下内容：

- `SetPoint`、`ClearAllPoints`、`SetSize`、`SetWidth`、`SetHeight`；
- 父子关系、层级关系、行列数量和滚动范围；
- `OnClick`、`OnTextChanged`、拍卖、交易或账单业务脚本；
- 账单数据、拍卖状态、协议消息或用户已有透明度设置。

实现必须可重复调用。重复应用同一主题不得创建对象、叠加脚本、改变几何或累积透明度。

主题切换只改变显示。它不得修改账单、拍卖、交易、角色总览或装备过滤数据，不得重建业务状态，不得新增插件消息或外部通信。

主题偏好使用枚举 `BiaoGe.BGNext.settings.uiTheme`，只允许 `"classic"` 或 `"preview"`。首个版本缺省值为 `"classic"`；只有用户主动切换才写入。实现该字段的提交必须同步更新数据清单和重置入口。

主题仅在 UI 初始化完成或用户主动切换时应用一次，不使用 `OnUpdate`、定时轮询或持续动画。切换流程为：

1. 读取并验证主题偏好；
2. 捕获关键控件的父级、锚点和尺寸，作为本次切换的几何快照；
3. 在受保护调用中应用样式；
4. 验证关键控件仍存在且几何快照未变化；
5. 任一步骤失败时恢复经典样式，将本次运行降级为经典主题，并只提示一次。

经典样式快照只保留在运行内存，不写入 SavedVariables。主题切换不得清空、迁移或重建账单数据。

## 分阶段交付

### 阶段 1：设计系统与账单兼容皮肤

- 建立令牌、基础组件和资源降级；
- 为团队账单增加不改变几何结构的 BGNext 预览皮肤；
- 建立几何兼容测试和经典主题回退；
- 在设置中提供“经典／BGNext 预览”切换，首版默认经典；
- 以平衡品牌和半透明战场可见性作为人工验收基准；
- 不改变任何非视觉业务行为。

### 阶段 2：高频非账单页面

- 迁移角色总览、装备过滤和价格预设；
- 验证大量数据、搜索、筛选和窗口缩放；
- 保持未迁移页面可用，不以半成品状态设为默认主题。

### 阶段 3：其余页面与一致性收尾

- 迁移心愿清单、设置、导入导出、提示和弹窗；
- 完成多客户端与分辨率矩阵；
- 根据维护者实机验收决定默认主题和经典主题保留周期。

每个阶段应拆成独立 Issue 和 PR，可单独测试、回退和发布。总 Issue 不直接授权一次性重写所有 UI。

## 安全、隐私与兼容性

- 不新增网络、聊天、插件频道、遥测、文件或剪贴板访问；
- 不读取或迁移第三方插件配置；
- 不保存玩家、团队、拍卖或交易历史；
- 唯一预期持久化变化是当前用户的主题偏好；
- 新资源必须记录来源和许可，并进入发布包审计；
- 不能依赖 EllesmereUI 的正式服专用 API、库或资源；
- 永久 60、TBC、时光服／熊猫人和正式服分别使用当前客户端可用的 Blizzard API 与模板；
- 未完成游戏内验证的客户端只能标记为代码覆盖、自动测试或未验证。

## 验收标准

- [ ] 主账单在经典主题和 BGNext 预览主题下的关键锚点、尺寸、分区、行列容量、底部操作区与截图边界一致。
- [ ] 装备最多的已支持团本填充约 100 条记录后，仍维持原版 BiaoGe 的查看、录入和一张图截图习惯。
- [ ] 不因字体、字号、边框或状态样式造成装备名、买家、金额或按钮文本新增截断。
- [ ] 按钮、页签、输入框、下拉、复选、禁用、选中、悬停、按下、焦点、错误和警告状态有一致且可辨认的样式。
- [ ] Logo 金、箭头青、业务状态色、装备品质色和职业色不会产生语义冲突。
- [ ] 非账单页面使用一致的导航、分组、搜索、空状态和危险操作规则。
- [ ] 主题切换不改变业务数据、当前拍卖、交易状态或账单内容。
- [ ] 主题初始化失败时安全回退经典外观，不阻断插件加载。
- [ ] 主题应用与悬停不新增持续轮询，不反复创建可复用 UI 对象。
- [ ] 1920×1080 和 2560×1440、常见 UI 缩放下完成账单截图与非账单页面密度验证。
- [ ] 正式服、永久 60、TBC、时光服／熊猫人按兼容性证据分别记录结果。
- [ ] 新增资源通过来源、许可、基线覆盖和发布包审计。
- [ ] 新增主题偏好时同步更新 `docs/security/data-inventory.md` 和清除／重置入口。
- [ ] 自动测试覆盖令牌完整性、颜色格式、应用幂等、经典恢复、异常回退和非法主题值降级。
- [ ] 自动几何契约记录并比较主窗口、团本页签、Boss／区域分区、汇总区和底部操作区的 Parent、Point、Width 与 Height。
- [ ] 代码扫描和回归测试确认主题层不替换业务事件，不新增 `OnUpdate`，不调用几何修改 API。
- [ ] 在复杂战斗场景背景下，以玩家现有透明度和约 58% 参考透明度分别验证装备名、买家、金额、输入焦点和错误提示可读性。

## 非目标

- 重排或重新发明团队账单；
- 把约 100 件装备改成分页、长滚动或必须多图分享；
- 修改拍卖、出价、交易、结算或插件消息协议；
- 复制 EllesmereUI 或其他插件的 UI 成品与资产；
- 首个阶段就删除经典主题；
- 为视觉效果引入持续动画、持续轮询或高频对象创建。

## 人工验收要求

该工作需要维护者进行视觉判断和游戏内验证，因此总 Issue 应标记为 `enhancement` 与 `ready-for-human`。自动化代理可以实现拆分后的安全子任务，但不能自行宣称主账单习惯、截图可读性或跨客户端视觉效果已经通过实机验收。
