# BGNext 价格预设设计

- 状态：首版设计已确认，等待维护者复核后进入实施计划
- 日期：2026-09-01
- 对应 Issue：#31
- 范围：团长起拍价、个人心理价、装备目录浏览、导入导出及现有窗口预填

## 1. 目标

为开团和参团前的价格准备提供一个本地页面，同时保持现有拍卖操作窗口精简：

1. 团长可以按客户端和团本维护多套起拍价方案。每套方案包含一个基础价格和少量单件覆盖价格。
2. 团员可以按角色和团本维护一套个人心理价，只保存明确设置过的单件装备。
3. 团长打开现有开拍窗口时，BGNext 只预填现有起拍价输入框。
4. 团员收到现有拍卖窗口时，BGNext 只预填现有心理价输入框。
5. 价格预填不自动开拍、不自动启用自动出价、不自动发送消息，也不在拍卖窗口增加常驻文字。

本设计是首版实施基线。页面尺寸、行高、每屏行数和安全上限可以根据 Titan 实机结果收紧，但不得静默改变两类价格的归属、优先级、手动确认和本地数据边界。

## 2. 已确认术语

- **团长起拍价**：团长或现有拍卖控制者在开团前维护的装备起拍价格。
- **我的心理价**：当前角色为自己明确设置的单件心理价格。
- **基础价格**：团长方案中适用于所有未设置单件覆盖价装备的默认起拍价。
- **单件覆盖价**：优先于基础价格的某个物品 ID 对应价格。
- **方案**：一个团本下的一套团长起拍价配置。个人心理价没有多方案。

界面不得使用较长的“负责人起始参考价”或“我的心理价格”。

## 3. 范围外

- 自动开始拍卖。
- 自动启用或发送出价。
- 根据成交记录、其他团队或网站数据自动估价。
- 保存价格变化历史、成交历史或其他玩家价格。
- 同步团队价格表或扩展现有拍卖协议。
- 从 Gargul、BiaoGe 或其他第三方插件导入专有格式。
- 在现有拍卖窗口显示价格来源、方案名称或额外说明区域。
- 首版对搜索结果批量改价。
- 读取、恢复或迁移已废止的 `BiaoGe.BGNext.auctionPresets` 自动出价配置。

## 4. 页面信息架构

页面使用三级浏览结构：

```text
团本
└─ Boss／杂项
   └─ 当前分组的装备掉落池
```

### 4.1 团本层

- 顶部显示当前客户端已有批准掉落目录的团本页签；空间不足时允许横向滚动或折叠为选择器。
- 用户可以在未组队时手动选择团本并提前维护价格。
- 切换团本后恢复该团本上次选择的团长方案、Boss 和列表位置。
- 资料状态为 `pending` 或没有批准掉落目录的团本不伪造物品，显示“暂无可用掉落资料”。

### 4.2 价格模式层

团本下方提供两个固定模式：

- `团长起拍价`
- `我的心理价`

切换模式时保留当前团本、Boss、搜索条件和滚动位置。

模式按钮下只显示当前模式的一句说明：

- 团长起拍价：`用于团长开团时自动填入自定义装备起拍价，最终仍由团长确认。`
- 我的心理价：`用于参团时自动填入已保存的心理价，不会自动启用或发送。`

这些说明只出现在价格管理页面，不进入现有拍卖窗口。

### 4.3 二级工具栏

团长起拍价模式保留完整方案工具栏：

- 当前方案选择器；
- 基础价格输入；
- “当前使用”状态；
- 新建、复制、重命名、删除；
- 导入、导出。

我的心理价只有一套，不显示方案管理按钮。工具栏显示：

- 已设置装备数量；
- 导入、导出；
- 清除本团本心理价。

说明行和工具栏分别存在，不能因为增加说明而删除方案操作。

### 4.4 Boss／杂项层

- 左侧为当前团本的 Boss 列表和固定“杂项”分组，显示各分组装备数量。
- 正常浏览一次只渲染当前 Boss 或杂项的装备池，不一次创建约 100 行界面对象。
- 可以提供“全部装备”节点，但仅在用户主动选择时使用复用行的滚动列表，不一次创建全部行对象。
- 搜索时跨当前团本查找，并在左侧显示各 Boss 的匹配数量；清除搜索后回到此前 Boss 和滚动位置。

### 4.5 装备池

每行显示：

- Blizzard 物品图标和装备名称；
- 所属 Boss／杂项（跨 Boss 搜索结果时显示）；
- 部位或类别；
- 品质；
- 当前生效价格；
- 单件价格输入；
- 清除单件价格的红叉操作。

团长模式未设置覆盖价时显示“基础 X G”；个人模式未设置时显示空输入或“未设置”，不借用团长价格。

输入价格后按 Enter 保存并移动到下一条当前可见结果。首版不提供批量修改搜索结果。

### 4.6 搜索与筛选

支持组合条件：

- 装备名称或物品 ID；
- 部位／类别；
- 品质；
- 设置状态：全部、已设置单件价格、未设置单件价格；
- 一键清除筛选。

名称搜索使用当前客户端物品缓存提供的本地名称。物品名称尚未加载时仍可通过物品 ID 定位；加载完成后增量更新可见行，不重建整页。

## 5. 数据模型

全部新数据位于 `BiaoGe.BGNext`。

### 5.1 团长起拍价

同一客户端家族内的本地角色共享：

```lua
leaderAuctionPricePresets[clientFamily][raidId] = {
    activePresetId = "p1",
    lastBossId = "XT002",
    presets = {
        p1 = {
            name = "普通团",
            basePrice = 100,
            itemPrices = {
                [itemId] = 500,
            },
        },
    },
}
```

- 每个团本首次打开时创建一套“默认方案”。
- 默认方案的 `basePrice` 从玩家当前本地 `BiaoGe.Auction.money` 复制。
- 老用户本地值不迁移、不覆盖。
- 本地值缺失或非法时才使用客户端默认值。
- 创建完成后，方案基础价与全局起拍价相互独立，不动态继承或反向写入。
- 同一团本可以新建、复制、重命名、删除和切换方案。
- 复制是一次性深复制；两套方案之后互不影响。
- 至少保留一套方案。删除当前方案需要确认并选择明确的回退方案。

### 5.2 我的心理价

按当前角色、客户端和团本隔离：

```lua
personalAuctionExpectations[clientFamily][realmId][player][raidId] = {
    itemPrices = {
        [itemId] = 1200,
    },
    lastBossId = "XT002",
}
```

- 每个角色、每个团本只有一套个人心理价。
- 不设置基础心理价。
- 只保存用户明确填写过的单件装备。
- 不按专精拆分，不随专精自动切换。
- 不在角色之间共享，不包含角色历史。

### 5.3 金额语义和限制

- 金额为整数金币，允许范围 `0–10,000,000 G`。
- `0` 是用户明确设置的有效价格；字段不存在才表示未设置。
- 每个团本最多 20 套团长方案。
- 方案名称最多 24 个字符。
- 每套团长方案或每份个人心理价最多 500 个单件价格。
- 所有表在写入时按白名单重建；未知字段和错误类型不进入 SavedVariables。

### 5.4 新安装默认值

只调整新安装、已清除配置或本地值不存在时使用的 `BiaoGe.Auction.money` 默认值：

| 客户端 | 新默认起拍价 |
| --- | ---: |
| 永久 60／探索赛季 | 100 G |
| TBC | 100 G |
| 巫妖王经典版 | 1,000 G |
| Titan／时光服 | 100 G |
| 熊猫人之谜 | 10,000 G |
| 大灾变 | 100,000 G |
| 正式服 | 100,000 G |

不得用一次性迁移覆盖老用户已经保存的全局起拍价。

## 6. 价格解析与现有窗口接入

### 6.1 团本解析

运行时不使用“最后编辑的价格页面”猜测团本。解析顺序为：

1. 现有主表格／当前副本上下文提供的团本 ID；
2. 当前客户端已批准目录中物品 ID 的唯一团本归属；
3. 无法唯一确定或物品不属于当前团本时返回未解析。

未解析时保持现有窗口值，不使用其他团本的方案。

### 6.2 团长起拍价

解析优先级固定：

```text
当前团本当前方案的单件覆盖价 > 当前方案基础价格
```

打开单件开拍窗口时：

1. 先执行现有权限检查和物品解析；
2. 查找当前团本及当前方案；
3. 将解析价格写入现有起拍价输入框；
4. 团长可以为本次操作手动修改；
5. 临时修改不写回方案；
6. 最终仍由团长点击现有开始按钮。

多件装备只有在每件装备解析成功且价格全部相同时才预填。价格不同、任一装备未解析或数据无效时保持现有输入，并显示一次简短提示，不选择任意一件价格。

### 6.3 我的心理价

收到单件拍卖窗口并完成物品加载后：

1. 按当前角色和解析出的团本读取单件心理价；
2. 有保存值时将原值写入现有心理价输入框；
3. 没有保存值时不修改输入框；
4. 保存值低于本次起拍价时仍填入原值，复用现有“心理价格需高于或等于起拍价”校验；
5. 不自动提高、清除或改写保存值；
6. 不自动启用自动出价，不自动调用发送函数。

### 6.4 拍卖窗口密度

现有开拍和竞价窗口不新增价格来源、方案名称、解释文字或额外常驻区域。新功能只改变已有输入框的初始值。异常继续使用现有提示能力；多件价格不一致只显示一次短提示。

## 7. 模块边界

建议实现为五个独立职责：

1. `AuctionPriceStore`：两类数据的校验、默认创建、方案操作和价格解析，不创建 Frame。
2. `AuctionPriceIndex`：从 BGNext 已批准目录投影团本、Boss、物品、部位和品质，并提供组合筛选。
3. `AuctionPriceCodec`：稳定导入导出、限制检查和导入预览，不调用聊天、剪贴板或外部 API。
4. `AuctionPriceUI`：三级页面、复用行、方案工具栏和导入导出弹窗。
5. `AuctionPriceRuntime`：在现有窗口创建／显示路径中执行最薄的查询和预填接入。

纯数据模块不得依赖 WoW Frame。运行时只通过模块公开接口查询价格，不直接遍历 SavedVariables。

## 8. 导入与导出

### 8.1 格式隔离

团长方案和个人心理价使用不同类型标识，不能相互导入。格式包含：

- 格式版本；
- 数据类型；
- 客户端家族；
- 团本 ID；
- 方案名称和基础价格（仅团长方案）；
- 物品 ID 与整数金币。

不包含角色名、玩家身份、装备名称、Boss 文案、团队信息、聊天、成交记录或第三方数据库。

### 8.2 导出

- 团长模式可导出当前方案或当前团本全部方案。
- 个人模式只导出当前角色当前团本的一份心理价。
- 同一数据多次导出结果稳定，键按固定顺序输出。
- 完整字符串显示在可选择编辑框中，由用户手动复制。
- 不调用聊天发送、插件消息、剪贴板、HTTP 或遥测。

### 8.3 导入预览和提交

粘贴后先解析，不立即写入。预览显示：

- 来源客户端和团本；
- 方案数量；
- 基础价格；
- 单件价格数量；
- 将覆盖的数量；
- 未知物品和无效数据数量。

团长方案默认作为新方案导入；同名生成明确的“名称（导入）”及必要序号。替换当前方案或全部方案必须由用户明确选择并二次确认。

个人心理价默认合并，相同物品使用导入值，提交前显示覆盖数量。清空后导入、替换全部心理价或忽略未知物品都必须由用户明确选择。

导入必须原子提交。文本超过 64 KB、格式版本不支持、客户端／团本不匹配、金额或数量超限、结构不完整时不修改现有数据。未知物品默认不写入；用户只能在预览后选择忽略未知项并继续或取消。

## 9. 性能与对象复用

- 团本目录在内存建立按团本、Boss、物品 ID、名称、部位、品质和设置状态访问的索引。
- 正常只渲染一个 Boss／杂项分组。
- “全部装备”和搜索结果使用固定数量的复用行，滚动时只更新行内容。
- 文本搜索防抖；物品缓存完成事件只刷新受影响的可见行。
- 切换价格模式或方案不重新创建页面控件。
- 不使用后台周期性全表扫描。

## 10. 错误处理

- 无权限：不改变现有权限结果，也不显示可操作的开拍入口。
- 团本或物品无法解析：保留现有输入值。
- 方案缺失或损坏：尝试读取经过校验的回退方案；无安全回退时不预填，并允许用户在管理页修复。
- 多件价格不一致：不预填并提示一次。
- 金额非法：输入框本地标红并禁止保存；不修改旧值。
- 导入失败：保留原数据并显示第一条可行动的错误原因。
- 资料缺失：管理页显示不可用状态，运行时不猜测价格。

## 11. 数据、隐私和来源

- 新字段登记到 `docs/security/data-inventory.md`。
- 价格数据只保存在玩家本地，不通过现有或新增插件频道同步。
- 不保存价格变更历史、使用次数、出价历史、其他玩家身份或其他玩家价格。
- 不新增游戏外传输、遥测、远程控制或外部可执行程序。
- 导入导出由用户主动触发，内容在操作前完整可见。
- Gargul 只作为“团长需要预先维护价格”这一高层工作流存在性的行为参考。本设计没有复制其源码、结构、文案、格式、数据库或素材。
- BiaoGe/BGLite 研究仍受 ADR-0003 约束；实现使用 BGNext 自己的模块边界和测试。

## 12. 自动化测试与验收

### 12.1 数据核心

- 客户端、团本、角色和方案隔离。
- 首次默认方案复制当前本地全局起拍价。
- 本地值缺失时使用正确客户端默认值。
- 不迁移或覆盖老用户全局值。
- 基础价、单件覆盖价和明确 `0 G` 的优先级。
- 复制方案深复制；删除当前方案需要合法回退。
- 个人心理价没有基础价、没有多方案且不跨角色共享。

### 12.2 目录与页面

- 团本 → Boss／杂项 → 装备池映射正确。
- 名称／物品 ID、部位、品质和设置状态可组合筛选。
- 搜索清除后恢复 Boss 与滚动位置。
- 大型团本不为约 100 件装备一次创建同量级永久行对象。
- 模式切换保留目录位置和筛选状态。

### 12.3 运行时接入

- 单件团长价格正确预填，临时修改不写回。
- 多件同价才预填；不同价或未解析时保留现有输入。
- 个人心理价原值预填；低于起拍价时复用现有校验。
- 没有个人价格时不修改窗口。
- 预填不调用开始拍卖、启用自动出价或发送消息。
- 无权限不能通过价格模块绕过现有控制。

### 12.4 导入导出

- 团长和个人格式互相拒绝。
- 当前方案、全团本方案和个人心理价稳定往返。
- 同名导入、合并覆盖、替换确认和未知物品预览正确。
- 超长、超数、超价、错误版本、客户端／团本不匹配全部原子失败。
- 源码扫描确认没有聊天发送、插件消息、剪贴板、HTTP 或遥测调用。

### 12.5 发布前人工验证

至少在 Titan／时光服完成：

- 约 100 件装备目录的 Boss 切换、搜索、筛选和连续录入；
- 方案新建、复制、重命名、删除和切换；
- 两类导入导出及错误预览；
- 单件、多件起拍价预填；
- 团员心理价预填且没有自动发送；
- 拍卖窗口尺寸和文字密度没有增加。

其他客户端只能按实际证据标记为代码覆盖、自动测试或未验证，不得把目录存在等同于实机支持。

## 13. 首版可调项

维护者尚未对所有细节完全确定，因此以下项目允许在不改变核心语义的前提下由实机验证调整：

- 团本页签在窄屏下改为选择器；
- 左侧 Boss 列表宽度和每屏装备行数；
- 搜索防抖时间；
- 方案数量、单件条目数量和导入文本上限只能收紧，放宽需重新评估性能；
- 导入预览按钮排列和提示措辞。

任何会改变本地／共享归属、自动发送边界、价格优先级、导入默认覆盖行为或老用户配置处理的调整，都必须先更新本规格并重新确认。
