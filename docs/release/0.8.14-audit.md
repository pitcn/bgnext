# BGNext 0.8.14 release audit

Scope: combine the previously reviewed confirmed single-character delete entry, the pending item-link bill preservation fix, and the own-character legendary item-level display fix. In-game notes, three locales, version identity, README and player-facing platform copy are synchronized. Feedback about gold totals, raid CD, wishlist discovery, bid-log discovery, reconciliation discovery and holiday CD is documented separately; unconfirmed reports and unimplemented holiday tracking are not claimed as fixed.

Data/privacy: no new persistent field, recipient, message, export or external runtime transmission. Delete reuses the existing family/realm/player target and confirmation; item-link guarding removes an accidental clear only. Legendary display reads Blizzard metadata for already collected own-item IDs and holds only transient callback state. Draw revision, owner identity and visibility checks reject stale callbacks. Existing item counts, equipped-item snapshots, upgrade quantities, user preferences, lifecycle and clear boundaries remain unchanged.

Provenance: original BGNext UI and regression work on verified BGLite 2.4.2. The previously reviewed Core/function2.lua override is unchanged in this release-preparation step. Newly updated upstream manifest entries are limited to the TOC version label and the three reviewed locale update-note changes. No external addon implementation or assets imported. BGLite identity and protocol versions remain 2.4.2 and 2.4.0; internal file names and save identifiers are not renamed.

Verification: 108 local Lua 5.1 suites pass, together with syntax, baseline and diff checks. All 262 files in the frozen package match their sources; the archive excludes quarantined modules, development documents and external executables, and NewBeeBox dry-run accepts its runtime tree (261 files after the official CLI omits addon_version.txt). Tests exercise real renderer/projection paths under simulated frame/item APIs; new coverage includes cached and uncached legendary levels, automatic completion, stale pooled labels, hidden windows, namespaced or unavailable APIs and invalid metadata. Existing scoped deletion, partial update, loot, auction, wishlist, settlement, retention and migration tests remain active. Review outcomes, exact hashes, commands and remote CI evidence are retained in local handoff records.

Independent review: prior deletion and pending-link fixes retain their existing separate critical reviews. One focused independent review of the newly added display code found no production defect and questioned whether the hide-state test really exercised visibility. A mutation replay removing only the visibility guard makes the original hide assertion fail, disproving that concern for the reviewed revision. The test now explicitly selects the latest callback to keep this intent clear. The earlier deletion review's Lua-loop-capture concern was likewise checked against real Lua 5.1 first-row deletion behavior rather than assumed correct. No unchanged implementation was resubmitted for duplicate review. Simulated evidence is not live-game proof.

Platform assessment (2026-10-28): the August official notice explicitly provides BGLite Pure Edition and encourages enhancements (https://wow.blizzard.cn/news/20260825/40565_1312084.html); the October notice restricts the named prohibited addons and their renamed/repackaged derivatives (https://wow.blizzard.cn/news/20261027/43790_1317856.html). Neither notice explicitly identifies BGNext. The existing BGNext NewBeeBox project remains public and approved at preflight. This provides a basis to submit the transparently identified BGLite enhancement for platform review; it is not a claim of specific operator endorsement, exemption, or account-safety assurance. No renaming or concealment is used. A platform rejection or suspension must be reported rather than bypassed.

Delivery: existing GitHub repository pitcn/bgnext, existing NewBeeBox project 25964 and existing DD plugin SN 381da18187344c0fa443cc2d52dec744. Preserve existing metadata, visibility, pricing, categories, associations and room linkage. Publish only the runtime graph package. Acceptance, review and public states are separate outcomes. Real-client interaction, SavedVariables reload, fonts/layout, network delivery and mixed-addon groups remain unverified; no broader compatibility claim is made.
