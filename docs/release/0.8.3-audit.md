# BGNext 0.8.3 发布审计

## 上游与行为对照

- 固定官方基准：BGLite 纯净版 2.4.2，commit `5649f58`，186 个文件。
- 本地行为参考：BiaoGe 2.3.5；只比较玩家可见拍卖、交易、角色总览和输入焦点行为，没有复制其新增源码或素材。
- 基础拍卖仍使用现有 `BiaoGeAuction` 协议；本版本没有新增或修改团队通信格式。
- 成功拍卖仍通过既有结束入口生成成交记录并填入同物品空白账单行；团长本人中标仍保留已付／欠款选择。
- BGNext 的差异是把账务保存放在所有界面刷新之前，并对延迟物品缓存、缺失目标名称和隐藏输入焦点做失败隔离。

## 发布阻断检查

- 自动化测试必须零失败。
- BGLite 基线与 BGNext 覆盖清单必须通过。
- 所有运行时 Lua 文件必须通过 Lua 5.1 语法检查。
- 发布 ZIP 必须只包含 TOC/XML 可达运行文件、批准的运行素材与必要说明，不得包含测试、开发文档、平台配置、凭据或停用历史模块。
- ZIP 内版本、游戏内版本、Git 标签、GitHub Release、新手盒子与网易 DD 必须统一为 0.8.3。
- GitHub 与网易 DD 使用同一份冻结 ZIP；新手盒子官方 CLI 会按平台规则重新打包并移除 `addon_version.txt`。除这个不参与运行的上游平台标记外，258 个运行文件逐字节一致。平台读取结果必须逐一核对版本和更新日志。

## 未覆盖风险

没有真实团队实机验证，因此不能声明所有客户端、NDUI 等第三方界面组合、跨服队伍或连续多拍场景均已验证。发布后如出现 Lua 错误，应优先收集完整错误堆栈、客户端版本、插件组合和复现操作。
