# BGNext 0.8.11 release audit

Scope: Titan P6 25-player Ulduar drop/token/wishlist catalog; four-column bill with 56 misc slots folded at 33; nondecreasing boss capacities; corrected clear boundary; deferred metadata for uncached automatic loot with captured scope and cancellation guards. Version, release history and Simplified Chinese/Traditional Chinese/English player notes are synchronized.

No new saved schema, collection, external communication, auction protocol or transaction behavior is introduced. Existing bill keys remain stable and other raid capacities remain unchanged. Deferred loot state is memory-only, bounded to 128 requests and 15 seconds, invalidated on relevant clear, scope changes and leave. Existing history stays untouched. See the data inventory and cache regression tests.

Provenance: approved BGLite 2.4.2 baseline and explicitly reviewed overrides; scoped AtlasLootMY item facts under ADR-0006; local restored BGLite studied read-only for behavior under ADR-0003. No third-party program source or assets imported. Runtime archive follows the approved TOC/XML graph and quarantine rules.

Verification: 105 Lua suites passed before release gate; maintenance parser tests, full high-risk gate and frozen package byte checks are recorded in the local handoff. Every changed baseline file was reviewed before refreshing its individual override hash. A separate release-gate lifecycle/layout review was requested; its actual result must be recorded rather than inferred from test success.

Compatibility limits: automated and simulated evidence covers these changes; no complete live Ulduar raid, actual saved-data reload or mixed-group in-game test has been observed. Installation into the maintainer's client is file-verified only. Reward products remain outside direct wishlist eligibility. The reported OS/EOE/SSC CD issue has no actual error trace and is outside this release's fixes. These limits are retained here without adding unrelated items to the player changelog.

Platform plan: GitHub v0.8.11 plus the existing NewBeeBox and NetEase DD projects. Retain existing platform metadata, visibility, pricing, associations and client selections; upload only the new version/package/changelog. Platform acceptance, moderation and public visibility must be reported separately. The same frozen ZIP is used for GitHub/DD; the official NewBeeBox CLI repacks the extracted runtime directory and omits addon_version.txt, which is a platform marker rather than runtime code.
