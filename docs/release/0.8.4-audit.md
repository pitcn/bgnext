# BGNext 0.8.4 发布审计

## 上游与回归范围

- 固定官方基准：BGLite 纯净版 2.4.2，commit `5649f58`，186 个文件。
- BiaoGe 和其他同类插件只用于玩家可见行为与兼容性研究；未复制其新增源码或素材。
- 本版本不改变 `BiaoGeAuction` 通信协议，不新增 SavedVariables 字段，不扩大团队消息接收范围。
- 重点回归链为：拍卖结束、买家/金额填表、交易匹配、欠款分配、总消费、组合快捷键、装备过滤和临时对账边界。

## 0.7.0—0.8.0 回归原因与防复发措施

历史问题不是单一 API 报错，而是新增功能直接改变原版核心入口的优先级、数据前置条件和事件顺序；当时部分测试只检查源码片段或孤立辅助函数，无法发现“记录存在但买家、金额或欠款错误”这类业务失败。

从本版本开始，发布候选必须同时满足：

1. 所有 BGLite 基准覆盖文件与批准哈希一致。
2. 拍卖结果到交易欠款的测试执行正式生产匹配和保存分支，并核对具体业务字段。
3. 快捷键使用完整修饰键矩阵与原版优先级做差分验证。
4. 装备过滤验证同步调用边界，不允许异步回调晚于调用者返回。
5. 团队与对账事件按当前客户端类别验证；无证据的 API 或事件只能标记为未验证，不能由其他客户端结果代替。
6. UI 刷新或第三方皮肤异常不能阻断核心成交事实和账务写入。
7. 正式包与本地 Debug 包分别构建，正式包不得包含 `/bgndebug`、测试源码或本地发布配置。

## wowdoc 兼容性证据

- MoP 源码快照：`wow-ui-source/classic`，commit `ecadf9d3326fa87828cacca7f13c0ab5f41840a6`。
- Titan 源码快照：`wow-ui-source/titan`，commit `ba472e5e1b5580b557e3dbf02c9e5ff23b223347`。
- 两个快照都使用 `IsInRaid(LE_PARTY_CATEGORY_INSTANCE)` 表示副本团队类别，并声明 `GROUP_LEFT(category, partyGUID)`；BGNext 保持原 BGLite `IsInRaid(1)` 的数值语义，同时优先读取暴雪命名常量。
- 永久 60、周年服、巫妖王、大地的裂变和正式服仍需分别运行实机 Debug `compat` 场景；某一客户端 PASS 不构成其他客户端已验证。

## 发布阻断检查

- Lua 回归必须为零失败。
- 官方 BGLite 2.4.2 基准与 BGNext 覆盖清单必须通过。
- 所有运行时 Lua 文件必须通过 Lua 5.1 语法检查。
- 发布 ZIP 必须只包含 TOC/XML 可达运行文件、批准素材和必要说明，不得包含测试、Debug Tool、凭据、平台配置或停用历史模块。
- ZIP、游戏内版本、Git 标签、GitHub Release、新手盒子和网易 DD 的 BGNext 版本及更新日志必须统一为 0.8.4。
- 实机反馈必须同时记录 BGNext 版本、Interface、Build、客户端类别、测试命令与 PASS/FAIL/MANUAL 结果。
