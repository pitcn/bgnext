# 装备过滤默认配置全量审计：所有版本 / 所有职业 / 所有专精

日期：2026-08-31  
范围：BGNext 内置装备过滤默认方案（`Core/BGNext/EquipmentFilterProfiles.lua`、`EquipmentFilterSpecializations.lua`）在全部已声明客户端家族（vanilla / tbc / titan / mop / retail）、全部职业、全部专精／天赋树上的正确性。  
方法：先研究本机合法安装的 BiaoGe 2.3.5（多客户端发布包）与 BGLite 2.4.0 只读基线，把第三方源码转换为“行为事实 + 需求矩阵”，再按暴雪公开机制独立核对，最后逐项与 BGNext 当前实现比对。本记录不保存第三方源码摘录、数据表、内部标识、UI 文案或图标路径。

## 一、结论摘要

BGNext 当前默认配置只对 **猎人** 与 **圣骑士** 做了专精级覆盖；萨满、德鲁伊、战士、死亡骑士、武僧等混合职责职业仍共用职业基础配置，武器／护甲／坦克过滤普遍缺失或错误。职业基础配置的护甲与武器表也包含多处与机制不符的错误。词缀目录只做了“精通／全能”的版本开关，未覆盖韧性、护甲穿透、精准、急速、回蓝、格挡等逐版本可见性，且默认词缀过滤引用了部分版本不存在的词缀，存在运行时风险。

需修正的高置信度问题分为四组（详见第三、四节）：

1. **职业基础武器／护甲表错误**（恶魔猎手多出匕首、唤魔师漏拳套；盗贼／武僧／恶魔猎手／唤魔师／战士／死亡骑士／猎人的护甲底表混入或遗漏类型）。
2. **护甲按版本收紧缺失**（护甲专精于 Cataclysm 4.0.1 引入；vanilla/tbc/titan 应允许更低护甲，mop/retail 应收紧到本职业最高护甲）。
3. **混合职责职业缺少专精级武器／护甲覆盖**（战士、萨满、德鲁伊、死亡骑士、武僧；圣骑士覆盖不完整）。
4. **词缀逐版本可见性与默认过滤不完整**（韧性/护甲穿透/精准/急速/回蓝/格挡等）。

## 二、版本与家族映射（行为事实）

### 2.1 BiaoGe 的客户端版本分支

参考版本用 `select(4, GetBuildInfo())` 得到的数字版本 `ver` 划分子集。经核对，其布尔分支语义为：

- `verLess2`：`ver < 30000`，即永久 60 与 TBC。
- `verLess3`：`ver < 40000`，即 60 / TBC / WotLK(含泰坦) 等“天赋树时代”。
- `verOver3`：`ver >= 30000`，即 WotLK(含泰坦) 及之后。
- `verOver4`：`ver >= 40000`，即 Cataclysm 及之后。
- `IsVanilla`（`ver<20000`）、`IsTBC`（20000–30000）、`IsWLK`（30000–40000，其中 `IsTitan` 为 `ver>=38000`）、`IsCTM`（40000–50000）、`IsMOP`（50000–60000）、`IsRetail`（`ver>=110000`）。

### 2.2 映射到 BGNext 已声明家族

BGNext 目录只声明 `vanilla`、`tbc`、`titan`、`mop`、`retail`（`wrath`、`cata` 由适配器识别但无目录，回落为职业基础配置）。对应关系：

| BGNext 家族 | verLess2 | verLess3 | verOver3 | verOver4 | 护甲专精 | 远程栏 |
|---|---|---|---|---|---|---|
| vanilla | 是 | 是 | 否 | 否 | 无 | 有 |
| tbc | 是 | 是 | 否 | 否 | 无 | 有 |
| titan | 否 | 是 | 是 | 否 | 无 | 有 |
| mop | 否 | 否 | 是 | 是 | 有 | 无 |
| retail | 否 | 否 | 是 | 是 | 有 | 无 |

关键机制事实（来自暴雪公开机制，非第三方私有数据）：

- **远程武器栏移除**与**护甲专精（满本职业护甲 +5% 主属性）**都在 Cataclysm 4.0.1 引入。因此“经典（保留远程栏 / 允许低护甲）”与“现代（无远程栏 / 收紧护甲）”在 BGNext 五个家族中的分界一致：`{vanilla, tbc, titan}` 为经典，`{mop, retail}` 为现代。
- 泰坦之握（狂怒战士双持双手武器）在 WotLK 3.0 引入，因此狂怒战士在 vanilla/tbc 双持单手、在 titan/mop/retail 双持双手。
- 精准在 TBC 2.3 引入、WoD 6.0 移除；护甲穿透在 WotLK 引入、Cataclysm 移除；韧性在 TBC 引入、WoD 移除；全能替代韧性后仅正式服存在。

### 3.2 BGNext 现状与差异

对照 `EquipmentFilterProfiles.lua` 的 `allowedArmor` / `allowedWeapons`：

- **护甲表无版本二分**：当前单一静态表，且多处混入或遗漏。
- **盗贼**：当前保留 `{布甲, 皮甲}`，应仅 `{皮甲}`（布甲混入，错误）。
- **武僧**：当前保留 `{布甲, 皮甲}`，应 `{皮甲, 副手}`（漏副手、混布甲，错误）。
- **恶魔猎手**：当前保留 `{布甲, 皮甲}`，应仅 `{皮甲}`（错误）。
- **唤魔师**：当前保留 `{副手, 布甲, 皮甲, 锁甲}`，应仅 `{锁甲}`（错误）。
- **战士／死亡骑士**：当前保留含布甲，经典应不含布甲（错误）。
- **猎人**：当前保留含布甲，应 `{皮甲, 锁甲}`（错误）。
- **恶魔猎手武器**：当前含匕首（应无匕首，错误）。
- **唤魔师武器**：当前漏拳套（错误）。
- **盗贼远程武器**：经典应保留弓/弩/枪/投掷（远程栏属性桩），当前一律过滤（错误）。

## 五、词缀：逐版本可见性与默认过滤

### 5.1 目标可见性矩阵（行为事实 → 需求）

“✓”表示该词缀在该客户端存在、可在规则编辑器中显示并可被默认方案过滤；“—”表示不存在。力量/敏捷/智力在正式服不再是词缀（改为主属性选择），其余版本均为普通词缀。

| 词缀 | vanilla | tbc | titan | mop | retail |
|---|---|---|---|---|---|
| 力量 / 敏捷 / 智力 | ✓ | ✓ | ✓ | ✓ | — |
| 精神 | ✓ | ✓ | ✓ | ✓ | — |
| 法力回复 | ✓ | ✓ | ✓ | — | — |
| 防御 / 招架 / 躲闪 | ✓ | ✓ | ✓ | ✓ | — |
| 格挡 | ✓ | ✓ | ✓ | — | — |
| 攻击强度 | ✓ | ✓ | ✓ | ✓ | — |
| 命中 | ✓ | ✓ | ✓ | ✓ | — |
| 爆击 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 急速 | — | ✓ | ✓ | ✓ | ✓ |
| 精准 | — | ✓ | ✓ | ✓ | — |
| 护甲穿透 | — | — | ✓ | — | — |
| 法术强度 | ✓ | ✓ | ✓ | ✓ | — |
| 精通 | — | — | — | ✓ | ✓ |
| 全能 | — | — | — | — | ✓ |
| 韧性 | — | — | — | ✓ | — |

（vanilla 无急速：急速等级于 TBC 2.0 引入；vanilla 无精准：精准于 TBC 2.3 引入；护甲穿透仅 WotLK；韧性与全能互斥且仅 MoP / 正式服分别存在。）

### 5.2 默认词缀过滤（角色级）

BGNext 采用“过滤 = 含该词缀即过滤”的最小错误职责模型，仅过滤明显错职责的词缀，主属性由 `primaryStat` 独立处理。逐版本可用后：

| 角色 | 默认过滤词缀（按版本） |
|---|---|
| 物理（力量/敏捷近战、敏捷远程） | vanilla/tbc/titan/mop：法术强度；retail：无 |
| 法系/治疗 | vanilla：攻击强度；tbc：攻击强度、精准；titan：攻击强度、护甲穿透、精准；mop：攻击强度、精准；retail：无 |

正式服默认不按词缀过滤错职责（暴雪机制仅保留主属性，词缀过滤退化为空），与“正式服仅主属性选择”一致。

### 5.3 BGNext 现状与差异

- `getRuleCatalog` 仅剥离“非 retail/mop 的精通”与“非 retail 的全能”，未剥离韧性（仅 mop）、护甲穿透（仅 titan）、精准（vanilla/retail 无）、急速（vanilla 无）、回蓝与格挡（mop/retail 无）等，且正式服仍显示力量/敏捷/智力等已非词缀的条目。
- 默认词缀过滤（`ROLES`）全版本同一份：法系/治疗全版本过滤 `{攻击强度, 护甲穿透, 精准}`，物理全版本过滤 `{法术强度}`。这会让 vanilla 过滤不存在的护甲穿透/精准、retail 过滤不存在的攻击强度/护甲穿透/精准/法术强度，既不符合机制，也有引用缺失全局字符串的运行时风险。

## 六、主属性与坦克

- **主属性**：BGNext 现有 `ROLES` 主属性映射（力量/敏捷/智力按角色）经核对正确，无需改动。
- **坦克**：`tankOnly` 仅在 titan/mop 为真（对应“WotLK 及之后、非正式服才启用坦克词缀过滤”）。已实现，保持不变。

## 七、修订方案（独立实现）

1. `EquipmentFilterProfiles.lua`：修正恶魔猎手/唤魔师武器；将护甲表改为经典/现代二分，修正盗贼/武僧/恶魔猎手/唤魔师/战士/死亡骑士/猎人护甲底表；`armorFilter` 按 `family` 选择保留集；为经典盗贼补回远程武器。
2. `EquipmentFilterSpecializations.lua`：为战士、萨满、德鲁伊、死亡骑士、武僧增加专精级武器/护甲覆盖；补全圣骑士（防护护甲、惩戒布甲）；补全猎人经典远程武器保留。覆盖按 `specKey` 的角色与树/专精 ID 区分同角色不同武器需求（如武器 vs 狂怒、冰霜 vs 邪恶）。
3. `EquipmentFilterProfiles.lua` 的 `getRuleCatalog` 与角色默认词缀过滤：改用逐版本词缀存在表，按家族裁剪可见词缀与默认过滤词缀，避免引用不存在的词缀。
4. 过滤引擎（`Core/function2.lua` 的 `BG.FilterAll`）保持只执行当前方案显式规则，不新增职业/专精隐藏旁路。

- 上述默认值未经过任一真实客户端实机验证；均标注为“自动化测试/模拟”状态，不宣称实机支持。
- `wrath`、`cata` 家族无目录：适配器识别后回落为职业基础配置，符合设计（未核验不建目录）。
