# 拍卖成交写入主表参考研究（2026-09-06）

## 范围

本次只研究玩家可观察的记账行为和失败边界，未复制第三方实现、标识符、文本或资产。

研究对象：

- 原版 BiaoGe 2.3.5（维护者本地提供）；
- 仓库固定的官方 BGLite 2.4.2 纯净版基准（commit `5649f58`）；
- 本地参考包 BGForge 1.1.0；
- 本地参考包 BGLite 白云飞整合版 26.9.5。

## 行为结论

这些版本都把“成功拍卖记录”作为自动生成账单的输入：装备已在表格中且自动生成账单开启时，成交买家和金额应最终出现在对应装备行。官方基准的自动路径会在成交后延迟重建买家和金额；团长或物品分配者则依赖交易记账，避免两个来源同时覆盖账单。

BGNext 需要同时满足两个兼容目标：

1. 成交记录出现后，匹配装备的买家和金额不能继续为空；
2. 不清空或重建已有手填内容和交易记账结果。

## BGNext 独立设计

BGNext 不复用参考插件的整表重建实现。每次成交记录落地后，立即定位当前账单中下一条“同物品且买家、金额均为空”的行，只写入这一笔成交。已有内容保持不变。团长本人拍中时仍由现有“已付／欠款／不记账”选择负责写入，避免自动写入抢在人工选择之前。

自动测试通过公开的拍卖结束入口验证：非本人买家在处理返回前写入；主写入不依赖延迟定时器；写入早于可选的团长附加记账；团长本人拍中不会产生竞争写入。
