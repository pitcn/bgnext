# BiaoGe 专精装备过滤参考研究

日期：2026-08-31  
研究对象：本机合法安装的 BiaoGe 2.3.5，多客户端发布包  
研究范围：装备过滤默认方案、角色专精识别与客户端版本分支

## 研究边界

本记录按 ADR-0003 编写。检查了第三方安装包中负责装备过滤默认值、角色专精识别和客户端分类的相关文件，但不保存源码摘录，不复制数据表、内部标识、UI 文案、图标路径或实现结构。

## 玩家可见行为与兼容事实

- 默认装备过滤不是只按职业提供。混合职责职业通常同时得到一个职业通用方案和多个职责／专精方案，例如坦克、物理输出、法系输出和治疗；这些方案分别选择可用主属性、伤害或治疗词缀、坦克词缀、武器及护甲。
- 纯输出且各专精装备需求相近的职业通常只提供职业通用方案。正式服猎人因远程与近战武器需求不同而提供专精方案。这说明是否拆分方案应由装备需求差异决定，而不是机械地要求每个职业都显示相同数量的方案。
- 默认值以“适合该方案的属性集合”为意图，再生成应过滤的其余属性。旧客户端的力量、敏捷、智力仍属于普通词缀规则；正式服另有独立的主属性选择。
- 版本差异会改变默认值：早期客户端允许的低护甲类型更宽松，后期客户端按护甲专精收紧；部分武器、远程栏、圣物和坦克属性只存在于特定客户端；熊与猫在支持四专精的客户端拆分，而旧天赋树客户端仍是三棵树。
- 非正式服虽然没有正式服式的独立主属性面板，专精默认方案仍通过词缀配置区分物理、法系和治疗装备。因此攻击强度、法术强度、治疗与回蓝词缀应由默认方案明确设置，不应成为过滤引擎中的隐藏职业判断。
- 装备过滤方案由玩家手动启用或停用，参考版本没有把当前识别专精可靠地自动绑定到相应过滤方案。BGNext 的“跟随当前专精”属于独立的交互改进。
- 参考版本在新式客户端记录当前专精索引；旧式客户端比较三棵天赋树点数。旧式比较在点数并列时会保留后遇到的树，因而可能产生看似确定但不可靠的结果。BGNext 必须把零点和并列视为未知。
- 专精更新由登录、天赋更新和新式客户端的专精变化事件触发，并延迟合并刷新。BGNext 可以采用事件合并这一行为需求，但应使用自己的适配器和状态模型。

## 对 BGNext 的派生需求

1. 默认配置粒度采用“客户端家族 + 职业 + 专精”，并由职业基础能力和专精覆盖规则独立合成。
2. 每个专精覆盖至少明确：主属性、物理／法术／治疗词缀、坦克词缀、武器和护甲；不能只换名称与图标。
3. 非正式服的攻击强度与法术强度互斥主要通过专精默认方案解决，过滤引擎继续只执行当前方案中的显式勾选。
4. 只有装备需求确实不同的专精才需要不同规则，但选择器仍可按客户端实际专精完整展示；规则相同的专精可以共享 BGNext 自有的规则构造器。
5. 新式客户端保存稳定专精 ID，不保存易变的列表序号；旧式客户端使用 BGNext 自有的客户端内天赋树键。
6. 自动跟随必须是显式模式。玩家选择自定义方案后停止跟随，未知专精时沿用现有方案且不猜测。
7. 默认配置必须逐客户端验证，不能把正式服配置直接下放到永久 60、TBC、周年时光服或熊猫人。

## 独立实现与明确排除

BGNext 将使用自己的客户端适配器、版本目录、规则合成、保存结构、界面和测试。不会引入或改写 BiaoGe 的默认数据表、数组顺序、方案索引、函数组织、内部名称、本地化文本、图标清单或存档格式，也不会读取或迁移 BiaoGe 的装备过滤存档。

## 追加研究：旧天赋树客户端的方案图标

追加研究对象：本机合法安装的 BiaoGe 1.24.4、BGLite 2.4.2 与 WeakAuras 5.20.7。

- 玩家可见事实：BiaoGe 的过滤方案快捷按钮使用方形且可辨识的技能／职责图标，而不是天赋页背景。WeakAuras 在现代专精 API 可用时使用暴雪返回的专精图标。
- 兼容事实：旧天赋树客户端 `GetTalentTabInfo` 的第二返回值是大尺寸天赋页背景纹理，直接填入 25×25 按钮会显示为透明区或裁切残影，不能当作专精图标。
- BGNext 派生需求：现代客户端继续使用暴雪专精 API 的方形图标；旧天赋树客户端必须从游戏 API 选取该树可辨识的方形技能纹理，并安全迁移早期测试包已保存的天赋页背景值。
- 独立实现：BGNext 不引入第三方图标映射表，而是通过暴雪 `GetNumTalents` / `GetTalentInfo` 选择每棵树最深层天赋的方形图标。原版的图标路径、映射顺序、内部标识、文本和资源均未复制、改写或打包。
