# 时光服 P6 奥杜尔准备与开服验收

日期：2026-10-02。基线：v0.8.10 / dd24fc4。状态：代码准备和模拟验证，尚未实机验收。

## 阶段规则

维护者已确认本次没有 10 人难度，按一个 25 人副本维护。现有 Titan 主表使用单一 `N` 掉落入口，本次不新增 `N10/N25/H10/H25`、H 菜单或第二个 CD。

两项假设保持待验证：历史 10 人掉落是否并入同 Boss 的 25 人掉落；困难模式是否仅增加掉落数量。维护工具把当前时光服已核验的同 Boss 物品去重放入同一 `N` 列表。因此无论增加数量还是出现困难专属物品，都无需另造一个客户端难度；若实机证明来源或难度语义不同，再针对证据修正。未核验的历史装备不会自动加入正式库。

[官方公告](https://wow.blizzard.cn/news/20260924/43790_1315082.html)确认 10 月 8 日开放、部分交互触发困难模式及治疗/输出两种橙锤，未提供完整物品 ID、掉落表或数量。

## 本轮准备

- 自有角色总览新增独立奥杜尔列，默认在旧阶段前，地图 603；只匹配 API 返回 `maxPlayers=25` 的锁定记录。旧 10 人及人数未知的记录不会冒充本次 CD。总数、进度与重置时间读取已有 API。
- 现有 25 人主表、十四 Boss、Encounter ID 继续复用。未调整基础拍卖协议、旧阶段选择、已保存的心愿和价格。
- 本地工具 `tools/prepare-titan-p6-loot.py` 不访问网络、不转换参考插件数据库、不在游戏内采集、不自动安装文件；输入维护者核验的 CSV，输出待审查 Lua。
- P6 测试覆盖 25 人 CD、旧 10 人排除、独立进度与重置，以及生成数据被真实心愿/价格模块接受。测试中的 90001 等数值是合成 fixture。

## 掉落资料准备

复制 `docs/maintenance/titan-p6-loot.csv` 到本地工作文件，填入当前时光服直接掉落，每件一行，同 Boss 可以多行，同装备可归属多个 Boss。

| 字段 | 含义 |
| --- | --- |
| boss | 当前主表 Boss 索引 1–14 |
| item_id | 当前客户端确认的正整数物品 ID |
| observed_mode | 实际观察 normal 或 hard，仅作维护记录，两者进入同一列表 |
| verified | 核验通过填 yes，其余 pending |
| evidence | 当前 Build、核验日期及脱敏来源文件、截图或合法公开资料引用；不放玩家名、聊天或账号资料 |

Boss 顺序沿用主表：1 烈焰巨兽、2 锋鳞、3 掌炉者、4 拆解者、5 钢铁议会、6 科隆加恩、7 欧尔利亚、8 霍迪尔、9 托里姆、10 弗蕾亚、11 米米尔隆、12 维扎克斯、13 尤格萨隆、14 奥尔加隆。实际事件映射仍须实机核验。

模板未填行会被拒绝。不要为通过检查而直接把 pending 改为 yes。从输入中删除未确认行，并在另一份研究文件保留候选资料。

```powershell
python tools/prepare-titan-p6-loot.py .local/p6-confirmed.csv --output .local/DB_Loot_Titan_P6.candidate.lua
```

默认要求十四 Boss 各有至少一个确认物品；这不证明完整掉落已收齐。审核部分资料可显式加 `--allow-partial`。空输入、非法 ID、无来源、未确认行及 10/H25 等非本次实际观察标签均拒绝输出；不会覆盖已有文件。

输出未挂入运行加载图。接入前审查实际物品、Boss 归属、兑换原件/成品、任务/碎片、共享掉落和小怪杂项，再将通过审核的原始掉落整合到 Titan 数据文件。工具只准备十四 Boss 直接掉落，不生成兑换映射、任务库、杂项或橙装监控名单。基线文件若改变，须逐项审查后更新其明确覆盖哈希。

记录 Build、Interface、时间、插件提交和证据等级；每项分别记录通过、失败或未测。

候选包仅包含 CD 接入和已有主表，未填充真实 P6 掉落或橙锤 ID；验收前不称“P6 完整支持”。
