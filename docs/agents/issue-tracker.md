# Issue tracker

BGNext uses GitHub Issues in `pitcn/bgnext` for bugs, feature requests, PRDs, security-safe tasks, and release blockers.

- Do not place vulnerability details or personal data in public issues; follow `SECURITY.md`.
- An agent may create or update an issue only when the user requests it or the active workflow explicitly authorizes it.
- Every implementation issue should state scope, privacy/data impact, compatibility target, acceptance tests, and verification commands.
- Pull requests must link the relevant issue when one exists and disclose baseline overrides, SavedVariables changes, protocol changes, third-party content, and unverified clients.
